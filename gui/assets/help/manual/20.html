21. Problèmes courants

21.1. sbom-generator introuvable

Symptôme : la génération échoue immédiatement avec une erreur du type sbom-generator: commande introuvable.

Solution : vérifiez que le binaire sbom-generator est accessible dans le PATH :

which sbom-generator
sbom-generator --version

Si le binaire est installé à un emplacement non standard, placez-le dans un dossier du PATH ou créez un lien symbolique :

ln -s /chemin/vers/sbom-generator /usr/local/bin/sbom-generator

21.2. syft / skopeo / cdxgen introuvable

Symptôme : la génération échoue avec le message syft introuvable ou non fonctionnel — requis pour --image.

Solution : installez l’outil manquant et vérifiez qu’il est dans le PATH :

# Syft
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh \
  | sh -s -- -b /usr/local/bin
syft version

# Skopeo (Fedora/RHEL)
sudo dnf install skopeo
skopeo --version

# cdxgen (npm, requiert Node.js)
npm install -g @cyclonedx/cdxgen
cdxgen --version

21.3. Échec de l’analyse OCI

Symptôme : Échec de l’analyse OCI : … dans le journal.

Causes possibles et solutions :

  • Image de registre inaccessible : vérifiez la connexion réseau et l’authentification (docker login ou skopeo login).

  • Archive tar corrompue ou format non reconnu : regénérez l’archive avec docker save <image> -o /path/image.tar (ou compressée : docker save <image> | gzip > /path/image.tar.gz). Les formats .tar, .tar.gz et .tgz sont supportés.

  • Répertoire OCI layout invalide : vérifiez que index.json est présent à la racine du répertoire.

21.4. grype introuvable

Symptôme : l’analyse Grype échoue avec le message grype introuvable. Installez-le : https://github.com/anchore/grype.

Solution : installez grype (voir Installer grype) et vérifiez qu’il est dans le PATH :

which grype
grype version

21.5. osv-scanner introuvable

Symptôme : l’analyse OSV-Scanner échoue avec un message du type osv-scanner: commande introuvable ou le fichier SBOM n’est pas trouvé.

Solution : vérifiez que osv-scanner est dans le PATH de votre session graphique (pas seulement dans le terminal) :

which osv-scanner
osv-scanner --version

Si osv-scanner est installé via go install dans ~/go/bin, ce dossier n’est souvent pas dans le PATH graphique. Ajoutez-le dans ~/.profile :

export PATH="$HOME/go/bin:$PATH"

Puis reconnectez-vous ou relancez le GUI.

21.6. trivy introuvable

Symptôme : l’analyse Trivy échoue avec un message du type trivy: commande introuvable.

Solution : vérifiez que trivy est dans le PATH :

which trivy
trivy --version

Installez-le si nécessaire (voir Installer trivy (optionnel)).

21.7. La base de données Trivy est obsolète

Symptôme : Trivy affiche un avertissement sur l’âge de sa base de données.

Solution : laissez --skip-db-update décoché (comportement par défaut) pour que Trivy mette à jour sa base automatiquement au lancement. En environnement hors-ligne, mettez à jour manuellement :

trivy image --download-db-only

21.8. Aucune vulnérabilité détectée malgré un SBOM chargé

Causes possibles :

  • Le fichier SBOM sélectionné n’est pas un format reconnu par grype. Grype supporte nativement CycloneDX JSON (.cdx.json) et SPDX JSON (.spdx.json). Le format SPDX 3.0 JSON-LD peut nécessiter une version récente de grype.

  • La base de données de vulnérabilités grype est obsolète. Grype la met à jour automatiquement au premier lancement, mais peut avoir besoin d’une mise à jour manuelle :

    grype db update

  • La version RHEL sélectionnée dans Distro ne correspond pas aux paquets du SBOM. Essayez (aucune) pour laisser grype détecter automatiquement.

21.9. Avertissements de licence

Symptôme : des lignes Warning: licence inconnue pour 'paquet' apparaissent dans la progression.

Explication : sbom-generator n’a pas pu déterminer la licence SPDX du paquet. Le SBOM est généré quand même avec la valeur NOASSERTION pour la licence concernée.

Solution : utilisez un fichier override de licences (--license-map) pour définir manuellement la licence des paquets non reconnus.

21.10. Le score sbomqs n’apparaît pas

Causes possibles :

  • sbomqs n’est pas installé ou n’est pas dans le PATH. Vérifiez avec which sbomqs. Si absent, installez-le (voir Installer sbomqs (optionnel)).

  • L’option Score qualité sbomqs n’est pas cochée dans la section Options.

  • Aucun fichier JSON SBOM n’a été généré dans la session courante. sbomqs ne s’exécute que sur les formats .cdx.json, .spdx.json ou .jsonld. Assurez-vous qu’au moins un de ces formats est sélectionné.

21.11. La conversion PDF échoue

Symptôme : le message asciidoctor-pdf introuvable apparaît dans les logs (génération SBOM) ou dans le message de confirmation (export AsciiDoc + PDF d’un onglet Grype/OSV-Scanner/Trivy — le fichier .adoc est alors tout de même produit).

Solution : installez asciidoctor-pdf (voir Installer asciidoctor-pdf (optionnel)).

Si asciidoctor-pdf est installé mais introuvable, assurez-vous que le dossier des gems Ruby est dans le PATH :

gem environment gemdir
# Exemple : /home/user/.local/share/gem/ruby/3.2.0
export PATH="$HOME/.local/share/gem/ruby/3.2.0/bin:$PATH"
