16. Onglet Arborescence SBOM

L’onglet Arborescence SBOM permet d’explorer les composants d’un fichier SBOM (CycloneDX ou SPDX) sans ouvrir un éditeur JSON.

  ┌─ Fichier : [ sbom.cdx.json ▼ ]  [📂 Ouvrir…]                      ─┐
  │  CycloneDX 1.6  •  Mon Application 2.1.0  •  246 composants          │
  ├─ Grouper par : [Aucun] [Type] [Licence]                               │
  ├────────────────────────────────────────────────────────────────────────┤
  │ ▶ rpm  (132)                                                           │
  │ ▼ python  (89)                                                         │
  │    requests  2.31.0  MIT  pkg:pypi/requests@2.31.0                    │
  │    urllib3   1.26.14 MIT  pkg:pypi/urllib3@1.26.14                    │
  │    ...                                                                 │
  │ ▶ deb  (25)                                                            │
  └────────────────────────────────────────────────────────────────────────┘

16.1. Sélection du fichier SBOM

Le menu déroulant liste les fichiers SBOM générés dans la session courante. Le premier fichier .cdx.json, .spdx.json ou .spdx3.jsonld est sélectionné automatiquement. Les SBOM de couche (--per-layer) n’y figurent pas : ils s’ouvrent depuis le sélecteur de couche (voir Navigation par couche (--per-layer)).

Le bouton Ouvrir… permet de charger n’importe quel fichier du système de fichiers.

Formats supportés :

  • CycloneDX 1.6 — .cdx.json (champ components[])

  • SPDX 2.x — .spdx.json (champ packages[])

  • SPDX 3.0 JSON-LD — .spdx3.jsonld

16.2. Barre d’informations

Après le chargement, une ligne de métadonnées s’affiche :

  • Format et version du SBOM

  • Nom du document / composant principal

  • Nombre total de composants

16.3. Groupement

Le sélecteur Grouper par propose trois modes :

Aucun

Tous les composants dans une liste plate triée par nom

Type

Regroupement par type de paquet (rpm, python, deb…)

Licence

Regroupement par expression de licence SPDX

Couche

SBOM produit avec --per-layer uniquement : regroupement par couche d’origine (Couche 01, Couche 02… dans le SBOM global) ou par changement (Ajoutés / Modifiés dans un SBOM de couche)

Les icônes à droite du sélecteur déplient ou replient tous les groupes.

Les groupes sont repliables. Cliquez sur l’en-tête d’un groupe pour l’ouvrir ou le fermer.

16.4. Détails d’un composant

Cliquez sur un composant pour afficher ses détails (champ expansible) :

  • PURL (Package URL) — cliquable pour copier dans le presse-papiers

  • Version

  • Type

  • Licence

  • Couche — couche d’origine (SBOM global) ou changement (SBOM de couche), pour un SBOM produit avec --per-layer

Note
 Les composants sans PURL dans le SBOM n’affichent pas ce champ.

16.5. Navigation par couche (--per-layer)

Quand le fichier ouvert appartient à un jeu produit avec --per-layer (SBOM global ou SBOM de couche), un bandeau N couche(s) s’affiche sous la barre de fichier, dans cet onglet comme dans la Visionneuse SBOM :

  • un menu déroulant SBOM global / Couche 1/N (digest) … ouvre directement le SBOM choisi ; pour chaque couche, il rappelle les compteurs (+ajoutés ~modifiés -supprimés) et l’instruction de build ;

  • sous le menu, la description du document affiché : digest, instruction, compteurs de la couche (ou nombre de couches et mode pour le global) ;

  • un badge N supprimé(s) liste au survol les composants supprimés par la couche (mode rootfs).

Les fichiers d’un même jeu sont retrouvés par leur nom dans le répertoire du fichier ouvert (<base>.<ext> et <base>.layer-NN-<digest>.<ext>, même format) : la navigation fonctionne aussi pour un jeu ouvert via Ouvrir….

16.6. Persistance de l’état

L’onglet mémorise son état (fichier sélectionné, groupement, groupes ouverts/fermés) lors de la navigation entre onglets.
