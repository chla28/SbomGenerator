10. Onglet Trivy — Analyse de vulnérabilités

L’onglet Trivy utilise l’outil d’Aqua Security. Il propose des options supplémentaires par rapport à OSV-Scanner et Grype.

  ┌───────────────────────────────────────────────────────────────────┐
  │  [ Fichier SBOM ] [ Image de conteneur ]                          │
  │  Fichier SBOM : [ /projet/sbom.cdx.json         ] [Choisir ▾]   │
  │                                                                   │
  │  Sévérités : [CRITICAL] [HIGH] [MEDIUM] [LOW] [UNKNOWN]          │
  │  [ ] --ignore-unfixed   [ ] --skip-db-update                     │
  │  trivy.yaml   : [                               ] [Choisir ▾]   │
  │                                                      [Analyser]  │
  ├───────────────────────────────────────────────────────────────────┤
  │  ⚠ 4 vulnérabilité(s) : 1 CRITICAL, 3 HIGH                       │
  ├───────────────────────┬───────────────────────────────────────────┤
  │ [Vulnérabilités (4)]  │ [JSON brut]                               │
  └───────────────────────┴───────────────────────────────────────────┘

10.1. Indicateur de version

Même comportement que dans l’onglet Grype (voir Indicateur de version), appliqué à trivy. Le badge est affiché en haut du panneau de configuration dès que la vérification de démarrage est terminée.

10.2. Prérequis

trivy doit être installé et accessible dans le PATH (voir Installer trivy (optionnel)).

10.3. Sélection de la source à analyser

Même bascule Fichier SBOM / Image de conteneur, mêmes formats acceptés en mode image (registre, archive locale, répertoire OCI layout) que dans l’onglet Grype (voir Sélection de la source à analyser), y compris le champ optionnel Plateforme (--platform, ex. linux/arm64).

En mode Fichier SBOM, Trivy est lancé via sa sous-commande trivy sbom ; en mode Image de conteneur, via trivy image (une archive ou un répertoire local est alors passé via --input, une référence de registre en argument direct).

Note
 Sur un SBOM CycloneDX/SPDX généré par sbom_generator avec le backend syft, il est normal que le mode Fichier SBOM trouve quelques CVE Java de plus que le mode Image de conteneur sur la même image — ce n’est pas un faux positif du SBOM, mais une sous-détection de l’analyseur de jars intégré à Trivy pour les jars sans pom.properties (ex. rebuilds internes Red Hat), que le cataloguer de syft détecte via le nom de fichier là où Trivy échoue. Voir [sec-pourquoi-ecarts-scanners] pour le détail avec des chiffres réels.

L’option Par couche est disponible en mode image, comme pour Grype ; en rattachement, la couche indiquée par Trivy lui-même (Layer.DiffID) est utilisée — voir Analyse par couche (source « Image de conteneur »).

10.4. Options de scan

10.4.1. Filtre de sévérités (--severity)

Cochez une ou plusieurs sévérités pour limiter l’analyse. Si aucune n’est cochée, toutes les sévérités sont analysées.

Niveaux disponibles : CRITICAL, HIGH, MEDIUM, LOW, UNKNOWN.

10.4.2. --ignore-unfixed

N’affiche que les vulnérabilités pour lesquelles une version corrigée est disponible. Équivalent à --only-fixed dans Grype.

10.4.3. --skip-db-update

Empêche Trivy de mettre à jour sa base de données locale au démarrage. Utile en environnement hors-ligne ou pour des analyses répétées rapides lorsque la base est déjà à jour.

10.4.4. Fichier de configuration (trivy.yaml)

Chemin vers un fichier de configuration Trivy au format YAML. Permet de définir des règles d’ignorance, des proxies, des registres privés, etc.

Ce paramètre est optionnel. Le bouton Choisir propose un filtre .yaml / .yml ou tous les fichiers.

10.5. Commande équivalente

En mode Fichier SBOM, Trivy est lancé avec les arguments :

trivy sbom --format json --quiet \
  [--severity CRITICAL,HIGH,...] \
  [--ignore-unfixed] \
  [--skip-db-update] \
  [--config trivy.yaml] \
  /chemin/vers/sbom.cdx.json

En mode Image de conteneur :

trivy image --format json --quiet \
  [--severity CRITICAL,HIGH,...] [--ignore-unfixed] [--skip-db-update] \
  [--config trivy.yaml] [--platform linux/arm64] \
  nginx:latest
# ou, pour une archive/un répertoire OCI local :
trivy image --format json --quiet [...] --input /chemin/vers/image.tar

10.6. Résultats

Même interface que les onglets Grype et OSV-Scanner : barre de recherche + tri + export CSV/AsciiDoc+PDF, filtres par sévérité, fusion des doublons visuels (badge ×N, voir [sec-vue-table]), puis liste des vulnérabilités.

Export CSV (bouton ⬇) : colonnes Sévérité, CVE/ID, Paquet, Version installée, Version corrigée, Titre, Emplacements.

Export AsciiDoc + PDF (bouton ⬥) : même rapport que sur les onglets Grype/OSV-Scanner (résumé par sévérité + tableau détaillé, conversion PDF automatique si asciidoctor-pdf est installé) — voir [sec-vue-table].

La colonne Titre correspond au champ Title du JSON Trivy (description courte de la CVE). Elle apparaît en sous-titre de chaque entrée dans la liste.

Filtre par date : même barre que l’onglet Grype (voir [sec-vue-table]). Le champ Publication correspond à PublishedDate du JSON Trivy, le champ Modification à LastModifiedDate. L’option Propager copie le filtre vers les onglets Grype et OSV-Scanner.
