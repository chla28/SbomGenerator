19. Flux de travail typiques

19.1. Scénario 1 — Générer un SBOM depuis une liste RPM

Étape Action

1

Préparez un fichier rpm.lst contenant la liste des paquets RPM (sortie de rpm -qa, un paquet par ligne)

2

Dans le champ Fichier d’entrée, sélectionnez rpm.lst

3

Dans le champ Chemin de base, saisissez le chemin de sortie : sbom ou /tmp/audit/sbom

4

Cochez CycloneDX 1.6 (format recommandé pour l’analyse grype)

5

Renseignez optionnellement le Nom du document (ex: RHEL 9.3 — Serveur HA)

6

Cliquez sur ▶ Générer le SBOM

7

Suivez la progression dans l’onglet Progression

8

À la fin, l’onglet Résultats s’ouvre automatiquement. Utilisez ↗ pour ouvrir le fichier JSON généré.

19.2. Scénario 1b — Générer un SBOM depuis une image OCI

Étape Action

1

Assurez-vous que syft (ou trivy / skopeo / cdxgen) est installé (voir Installer syft (optionnel))

2

Dans le champ Image OCI, saisissez la référence : nginx:latest, /path/ubuntu.tar (ou .tar.gz / .tgz), ou utilisez 📂 pour parcourir (archives tar ou répertoire OCI layout)

3

Sélectionnez le backend OCI si nécessaire (Syft est le défaut)

4

Dans le champ Chemin de base, saisissez le chemin de sortie : sbom

5

Cochez le(s) format(s) souhaité(s) (CycloneDX recommandé)

6

Cliquez sur ▶ Générer le SBOM. L’interface affiche d’abord le message Analyse de l’image OCI… pendant que l’outil analyse l’image, puis lance la génération du SBOM.

7

À la fin, l’onglet Résultats s’ouvre. Continuez avec Grype pour analyser les vulnérabilités (onglet Grype — le fichier SBOM est pré-rempli).

19.3. Scénario 2 — Générer un SBOM puis analyser les vulnérabilités avec Grype

Suite du scénario 1 :

Étape Action

9

Passez sur l’onglet Grype. Le champ Fichier SBOM est déjà rempli avec le .cdx.json généré à l’étape précédente.

10

Sélectionnez la version RHEL dans le menu Distro : ex. rhel:9

11

Laissez --platform linux, --add-cpes-if-none et --by-cve cochés

12

Optionnel : sélectionnez un seuil --fail-on (ex. high) et cochez --only-fixed pour filtrer sur les vulnérabilités corrigeables

13

Optionnel : renseignez le champ Template (-t) avec ./grype_csv.tmpl pour produire un export CSV

14

Cliquez sur Analyser

15

Consultez la vue Table pour un aperçu par sévérité, la vue JSON pour les détails techniques, et la vue Template pour l’export CSV

19.4. Scénario 2b — Croiser les résultats OSV-Scanner et Trivy

Étape Action

1

Après une génération SBOM, passez sur l’onglet OSV-Scanner. Le champ Fichier SBOM est pré-rempli.

2

Cliquez sur Analyser. Consultez la vue Vulnérabilités avec les filtres par sévérité.

3

Passez sur l’onglet Trivy. Le champ Fichier SBOM est également pré-rempli (les onglets mémorisent leur état lors de la navigation).

4

Optionnel : cochez --ignore-unfixed pour ne voir que les vulnérabilités corrigeables.

5

Cliquez sur Analyser. Comparez les résultats Trivy avec ceux d’OSV-Scanner pour détecter d’éventuels faux-positifs ou faux-négatifs.

6

Consultez la vue JSON brut de chaque onglet pour accéder aux métadonnées détaillées (CVSS, références, packages affectés).

19.5. Scénario 2c — Filtrer les CVE par période de publication

Étape Action

1

Après avoir lancé une analyse Grype (ou OSV-Scanner / Trivy), consultez l’onglet correspondant. La barre de filtre par date est visible au-dessus du tableau.

2

Pour n’afficher que les CVE publiées depuis le 1er janvier 2024, cliquez sur la chip Après le… et sélectionnez 2024-01-01 dans le calendrier. Le tableau se met à jour instantanément.

3

Pour ajouter une borne haute, cliquez sur Avant le… et sélectionnez la date de fin souhaitée.

4

Si vous souhaitez filtrer sur la dernière mise à jour plutôt que sur la date de publication initiale, changez le sélecteur Publication en Modification ou La plus récente.

5

Cochez Sans date pour inclure dans les résultats les CVE dont la date est absente des données du scanner (champ vide dans le JSON).

6

Cliquez sur Propager aux autres onglets pour appliquer le même filtre aux onglets OSV-Scanner et Trivy sans avoir à les re-configurer.

7

Pour effacer une borne, cliquez sur le × de la chip correspondante.

19.6. Scénario 3 — Évaluation de la qualité SBOM avec sbomqs

Étape Action

1

Installez sbomqs (voir Installer sbomqs (optionnel))

2

Dans la section Options, cochez Score qualité sbomqs

3

Lancez la génération normalement (format CycloneDX recommandé)

4

Après la génération, l’onglet Résultats s’ouvre et affiche le score sbomqs dans un encadré indigo sous la liste des fichiers

5

Sélectionnez le texte du score pour le copier dans un rapport

19.7. Scénario 4 — Rapport AsciiDoc + PDF

Étape Action

1

Cochez les formats AsciiDoc (et optionnellement d’autres formats)

2

Cochez Convertir en PDF (asciidoctor-pdf)

3

Optionnel : renseignez un chemin de PDF dans le champ qui apparaît

4

Lancez la génération. Le PDF est créé automatiquement après le .adoc.

5

Les deux fichiers (.adoc et .pdf) apparaissent dans l’onglet Résultats
