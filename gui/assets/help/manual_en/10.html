11. CRA Compliance tab — Cyber Resilience Act

The CRA Compliance tab produces a compliance report with Regulation (EU) 2024/2847 (Cyber Resilience Act) from an SBOM. It drives the sbom-generator cra subcommand (the binary configured in the settings) and displays its result.

Important

The report only covers the CRA requirements that can be verified automatically from an SBOM and a known-vulnerability analysis:

  • SBOM format and completeness — commonly used machine-readable format, dependency coverage (Annex I §2 point 1), data fields per component (BSI TR-03183-2: name, version, supplier, unique PURL/CPE identifier, hash, license), NTIA 2021 minimum elements;

  • vulnerability management — inventory of known vulnerabilities and availability of fixes (Annex I §2 points 1-2);

  • actively exploited vulnerabilities — any CVE in the CISA KEV catalog is flagged as triggering the obligation to notify ENISA within 24 h (art. 14).

The other CRA obligations (secure distribution of updates, effective coordinated disclosure policy, secure-by-default design, regular testing, regulatory notifications, EU declaration of conformity) are the manufacturer’s responsibility and are only listed. This report is not a declaration of conformity.

11.1. Filling in the form

SBOM file to assess: pre-filled with the first generated SBOM (.cdx.json / .spdx.json, otherwise .json). The Choose button opens a file picker.

Product metadata (optional): collapsible section — Manufacturer, Product, Product version, End of support (YYYY-MM-DD), Vulnerability reporting contact, URL of the coordinated disclosure policy. The Load a cra.yaml button imports these values from a file (key: value per line). The fields entered here take precedence over the file; missing values are deduced from the metadata.component of the SBOM.

Scan for known vulnerabilities: checked by default. Runs a scanner (Grype by default, or OSV-Scanner / Trivy / all three) to assess the vulnerability inventory and the availability of fixes, with CISA KEV / EPSS enrichment. Unchecked, the report is limited to the SBOM analysis and states that vulnerability management could not be attested.

11.2. Running and exporting

Assess: runs the analysis and displays the result under the form:

  • verdict banner — Compliant / Partial / Non-compliant on the verified scope, with the summary sentence;

  • four indicators — compliant SBOM fields, NTIA elements, vulnerabilities without a fix, actively exploited CVEs (KEV);

  • blocking items — list of the reasons for non-compliance, if any;

  • table of SBOM data fields (BSI TR-03183-2) with coverage and status per field;

  • reminder of the SBOM format, the number of components and dependency relationships, and the vulnerability count.

Export the PDF report: regenerates the complete report as a PDF (cover page, executive summary, product identification, detailed SBOM analysis, vulnerability management, manufacturer requirements, conclusion) and saves it at the chosen location. The PDF conversion requires asciidoctor-pdf.

A Non-compliant report is not an error: it lists the points to fix. Blocking reasons: non-machine-readable format, insufficiently filled mandatory field, vulnerability without an available fix, CVE in the CISA KEV catalog.
