9. OSV-Scanner tab — Vulnerability analysis

The OSV-Scanner tab uses Google’s tool to look for vulnerabilities from an SBOM file or a container image. Its interface is identical to that of the Grype tab.

  ┌───────────────────────────────────────────────────────────────────┐
  │  [ SBOM file ] [ Container image ]                                │
  │  SBOM file : [ /project/sbom.cdx.json           ] [Choose ▾]    │
  │  Toml config: [                                 ] [Choose ▾]    │
  │                                                      [Analyze]   │
  ├───────────────────────────────────────────────────────────────────┤
  │  ⚠ 3 vulnerability(ies): 1 Critical, 2 High                      │
  ├───────────────────────┬───────────────────────────────────────────┤
  │ [Vulnerabilities (3)] │ [Raw JSON]                                │
  └───────────────────────┴───────────────────────────────────────────┘

9.1. Version indicator

Same behavior as in the Grype tab (see Version indicator), applied to osv-scanner. The badge is displayed at the top of the configuration panel as soon as the startup check is finished.

9.2. Requirements

osv-scanner must be installed and reachable in the PATH (see Installing osv-scanner (optional)).

9.3. Selecting the source to analyze

Same SBOM file / Container image toggle as in the Grype tab (see Selecting the source to analyze). In SBOM file mode, the field is pre-filled with the last generated file; the Choose button offers:

  • Filtered type: .json and .jsonld files

  • All files

In Container image mode, the field accepts a registry reference (e.g. nginx:latest) or a local archive (docker save, through the dedicated button) — in .tar, .tar.gz or .tgz format.

Note
 Unlike Grype and Trivy, OSV-Scanner cannot read an OCI layout directory directly: only the archive is offered here. It also has no platform option (--platform).

The Per layer option is available in image mode, as for Grype — see Per-layer analysis (“Container image” source).

9.4. Optional configuration (toml)

Path to an osv-scanner.toml configuration file used to define ignore rules by vulnerability ID. This parameter is optional.

9.5. Starting the analysis

Click Analyze. In SBOM file mode, OSV-Scanner runs with:

osv-scanner --format json --sbom /path/to/sbom.cdx.json

In Container image mode, the subcommand changes (--sbom cannot scan an image):

osv-scanner scan image --format json nginx:latest
# or, for a local archive:
osv-scanner scan image --format json --archive /path/to/image.tar

An exit code of 1 indicates that at least one vulnerability was found (this is normal, not an error); a code greater than 1 indicates an error.

9.6. Results

9.6.1. Vulnerabilities view

Same interface as the Grype tab: search bar + sort + CSV export, severity filters, then the list of vulnerabilities.

  [ Search...                            ] [⬇]
  Filter : [Critical (1)] [High (2)] [Medium (0)] [Low (0)]  [Show all]

  ┌────────────┬────────────────────┬────────────────┬────────────────────────┐
  │ SEVERITY ↕ │ CVE/ID ↕           │ PACKAGE ↕      │ FIXED VERSION ↕        │
  ├────────────┼────────────────────┼────────────────┼────────────────────────┤
  │ CRITICAL   │ CVE-2023-12345     │ requests 2.28  │ 2.31.0                 │
  └────────────┴────────────────────┴────────────────┴────────────────────────┘

Search and sort: identical to the Grype tab (see [sec-vue-table]).

Merging of visual duplicates: same behavior (×N badge) as the Grype tab — see [sec-vue-table].

CSV export: the ⬇ button exports the filtered (already merged) view. Columns: Severity, CVE/ID, Package, Installed version, Fixed version, Ecosystem, Locations.

AsciiDoc + PDF export: the ⬥ button exports the same filtered view into an AsciiDoc report (summary by severity + detailed table), with automatic PDF conversion if asciidoctor-pdf is installed — see the full description in the Grype tab ([sec-vue-table]).

Date filter: same bar as the Grype tab (see [sec-vue-table]). The Published field corresponds to published of the OSV JSON, the Modified field to modified. The Apply option copies the filter to the Grype and Trivy tabs.

Columns:

  • Colored severity badge

  • CVE identifier (clickable — copies to the clipboard)

  • Name and version of the affected package

  • Fixed version (if available)

The severity is determined from the database_specific.severity field or from the CVSS scores present in the OSV JSON.

9.6.2. Raw JSON view

Displays the complete JSON returned by osv-scanner, useful to inspect the detailed metadata of each vulnerability.
