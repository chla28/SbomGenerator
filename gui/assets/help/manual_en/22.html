23. Typical workflows

23.1. Scenario 1 — Generating an SBOM from an RPM list

Step Action

1

Prepare an rpm.lst file containing the list of RPM packages (output of rpm -qa, one package per line)

2

In the Packages to analyze field, select rpm.lst

3

In the Base path field, enter the output path: sbom or /tmp/audit/sbom

4

Check CycloneDX 1.6 (recommended format for the grype analysis)

5

Optionally fill in the SBOM document name (e.g. RHEL 9.3 — HA Server)

6

Click ▶ Generate the SBOM

7

Follow the progress in the Progress tab

8

At the end, the Results tab opens automatically. Use ↗ to open the generated JSON file.

23.2. Scenario 1b — Generating an SBOM from an OCI image

Step Action

1

Make sure syft (or trivy / skopeo / cdxgen) is installed (see Installing syft (optional))

2

In the OCI image field, enter the reference: nginx:latest, /path/ubuntu.tar (or .tar.gz / .tgz), or use 📂 to browse (tar archives or OCI layout directory)

3

Select the OCI backend if needed (Syft is the default)

4

In the Base path field, enter the output path: sbom

5

Check the desired format(s) (CycloneDX recommended)

6

Click ▶ Generate the SBOM. The interface first displays the message Analysing OCI image … while the tool analyzes the image, then starts the SBOM generation.

7

At the end, the Results tab opens. Continue with Grype to analyze the vulnerabilities (Grype tab — the SBOM file is pre-filled).

23.3. Scenario 2 — Generating an SBOM then analyzing vulnerabilities with Grype

Continuation of scenario 1:

Step Action

9

Go to the Grype tab. The SBOM file field is already filled in with the .cdx.json generated in the previous step.

10

Select the RHEL version in the Distro menu: e.g. rhel:9

11

Leave --platform linux, --add-cpes-if-none and --by-cve checked

12

Optional: select a --fail-on threshold (e.g. high) and check --only-fixed to filter on fixable vulnerabilities

13

Optional: fill in the Template (-t) field with ./grype_csv.tmpl to produce a CSV export

14

Click Analyze

15

Look at the Table view for an overview by severity, the JSON view for the technical details, and the Template view for the CSV export

23.4. Scenario 2b — Cross-checking OSV-Scanner and Trivy results

Step Action

1

After an SBOM generation, go to the OSV-Scanner tab. The SBOM file field is pre-filled.

2

Click Analyze. Look at the Vulnerabilities view with the severity filters.

3

Go to the Trivy tab. The SBOM file field is also pre-filled (the tabs remember their state when navigating).

4

Optional: check --ignore-unfixed to only see fixable vulnerabilities.

5

Click Analyze. Compare the Trivy results with those of OSV-Scanner to detect possible false positives or false negatives.

6

Look at the Raw JSON view of each tab to access the detailed metadata (CVSS, references, affected packages).

23.5. Scenario 2c — Filtering CVEs by publication period

Step Action

1

After running a Grype (or OSV-Scanner / Trivy) analysis, open the matching tab. The date filter bar is visible above the table.

2

To only display the CVEs published since January 1st, 2024, click the After… chip and select 2024-01-01 in the calendar. The table updates instantly.

3

To add an upper bound, click Before… and select the desired end date.

4

If you want to filter on the last update rather than on the initial publication date, change the Published selector to Modified or Most recent.

5

Check Undated to include in the results the CVEs whose date is absent from the scanner data (empty field in the JSON).

6

Click Apply to other tabs to apply the same filter to the OSV-Scanner and Trivy tabs without having to reconfigure them.

7

To clear a bound, click the × of the matching chip.

23.6. Scenario 3 — Assessing SBOM quality with sbomqs

Step Action

1

Install sbomqs (see Installing sbomqs (optional))

2

In the Options section, check sbomqs quality score

3

Launch the generation normally (CycloneDX format recommended)

4

After the generation, the Results tab opens and displays the sbomqs score in an indigo box under the file list

5

Select the score text to copy it into a report

23.7. Scenario 4 — AsciiDoc + PDF report

Step Action

1

Check the AsciiDoc format (and optionally other formats)

2

Check Convert to PDF (asciidoctor-pdf)

3

Optional: fill in a PDF path in the field that appears

4

Launch the generation. The PDF is created automatically after the .adoc.

5

Both files (.adoc and .pdf) appear in the Results tab
