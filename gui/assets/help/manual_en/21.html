22. Troubleshooting

22.1. sbom-generator not found

Symptom: the generation fails immediately with an error such as sbom-generator: command not found.

Solution: check that the sbom-generator binary is reachable in the PATH:

which sbom-generator
sbom-generator --version

If the binary is installed in a non-standard location, put it in a folder of the PATH or create a symbolic link:

ln -s /path/to/sbom-generator /usr/local/bin/sbom-generator

22.2. syft / skopeo / cdxgen not found

Symptom: the generation fails with the message syft not found or not working — required for --image.

Solution: install the missing tool and check that it is in the PATH:

# Syft
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh \
  | sh -s -- -b /usr/local/bin
syft version

# Skopeo (Fedora/RHEL)
sudo dnf install skopeo
skopeo --version

# cdxgen (npm, requires Node.js)
npm install -g @cyclonedx/cdxgen
cdxgen --version

22.3. OCI analysis failure

Symptom: OCI analysis failed: … in the log.

Possible causes and solutions:

  • Unreachable registry image: check the network connection and the authentication (docker login or skopeo login).

  • Corrupted tar archive or unrecognized format: regenerate the archive with docker save <image> -o /path/image.tar (or compressed: docker save <image> | gzip > /path/image.tar.gz). The .tar, .tar.gz and .tgz formats are supported.

  • Invalid OCI layout directory: check that index.json is present at the root of the directory.

22.4. grype not found

Symptom: the Grype analysis fails with the message grype not found. Install it: https://github.com/anchore/grype.

Solution: install grype (see Installing grype) and check that it is in the PATH:

which grype
grype version

22.5. osv-scanner not found

Symptom: the OSV-Scanner analysis fails with a message such as osv-scanner: command not found or the SBOM file is not found.

Solution: check that osv-scanner is in the PATH of your graphical session (not only in the terminal):

which osv-scanner
osv-scanner --version

If osv-scanner is installed via go install in ~/go/bin, this folder is often not in the graphical PATH. Add it in ~/.profile:

export PATH="$HOME/go/bin:$PATH"

Then log in again or restart the GUI.

22.6. trivy not found

Symptom: the Trivy analysis fails with a message such as trivy: command not found.

Solution: check that trivy is in the PATH:

which trivy
trivy --version

Install it if needed (see Installing trivy (optional)).

22.7. The Trivy database is outdated

Symptom: Trivy displays a warning about the age of its database.

Solution: leave --skip-db-update unchecked (default behavior) so that Trivy updates its database automatically at launch. In an offline environment, update manually:

trivy image --download-db-only

22.8. No vulnerability detected despite a loaded SBOM

Possible causes:

  • The selected SBOM file is not a format recognized by grype. Grype natively supports CycloneDX JSON (.cdx.json) and SPDX JSON (.spdx.json). The SPDX 3.0 JSON-LD format may require a recent version of grype.

  • The grype vulnerability database is outdated. Grype updates it automatically on first launch, but may need a manual update:

    grype db update

  • The RHEL version selected in Distro does not match the packages of the SBOM. Try (none) to let grype detect it automatically.

22.9. License warnings

Symptom: Warning: unknown license for 'package' lines appear in the progress.

Explanation: sbom-generator could not determine the SPDX license of the package. The SBOM is still generated, with the value NOASSERTION for the license concerned.

Solution: use a license override file (--license-map) to manually define the license of unrecognized packages.

22.10. The sbomqs score does not appear

Possible causes:

  • sbomqs is not installed or is not in the PATH. Check with which sbomqs. If missing, install it (see Installing sbomqs (optional)).

  • The sbomqs quality score option is not checked in the Options section.

  • No JSON SBOM file was generated in the current session. sbomqs only runs on the .cdx.json, .spdx.json or .jsonld formats. Make sure at least one of these formats is selected.

22.11. The PDF conversion fails

Symptom: the message asciidoctor-pdf not found appears in the logs (SBOM generation) or in the confirmation message (AsciiDoc + PDF export of a Grype/OSV-Scanner/Trivy tab — the .adoc file is still produced).

Solution: install asciidoctor-pdf (see Installing asciidoctor-pdf (optional)).

If asciidoctor-pdf is installed but not found, make sure the Ruby gems folder is in the PATH:

gem environment gemdir
# Example: /home/user/.local/share/gem/ruby/3.2.0
export PATH="$HOME/.local/share/gem/ruby/3.2.0/bin:$PATH"
