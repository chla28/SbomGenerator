1. Introduction

1.1. What is an SBOM?

An SBOM (Software Bill of Materials) is a structured file listing all the components of a piece of software: packages, libraries, versions, licenses. It plays the role of a bill of materials, in the industrial sense of the term.

The most widespread formats are:

  • CycloneDX (JSON, recommended by OWASP and ANSSI)

  • SPDX (ISO/IEC 5962:2021 standard, adopted by the Linux Foundation)

1.2. What is Grype?

Grype (Anchore) is an open-source CVE vulnerability scanner. It analyzes an SBOM file and compares it with vulnerability databases (NVD, GitHub Security Advisories…) to identify the affected packages and their severity level.

Severity levels (from most critical to most benign):

Level Color in the UI Meaning

Critical

Dark red

Immediate exploitation, maximum impact (RCE, privilege escalation…)

High

Red-orange

Significant impact, likely exploitation

Medium

Orange

Exploitable under particular conditions

Low

Green

Limited impact, hard to exploit

Negligible

Grey

Theoretical impact, generally not exploitable in practice (Grype only)
Note
 The databases used by OSV-Scanner sometimes use the label MODERATE (GitHub Advisory, npm) instead of MEDIUM. The application unifies them automatically: any MODERATE severity is displayed as Medium in the table and the filters.

1.3. About the tool

SBOM Generator GUI is a Linux desktop graphical interface that orchestrates command-line tools:

  • sbom-generator: generates SBOM files from a list of packages or an OCI image

  • grype: analyzes the generated SBOMs to detect CVE vulnerabilities (Anchore)

  • osv-scanner: analyzes SBOMs to detect CVE vulnerabilities (Google)

  • trivy: analyzes SBOMs to detect CVE vulnerabilities (Aqua Security)

  • sbomqs: computes an SBOM quality score (optional)

  • asciidoctor-pdf: converts the AsciiDoc report to PDF (optional)

The interface lets you configure the options, follow the execution in real time, access the produced files, preview them, and run a vulnerability analysis without ever opening a terminal.

For each run, the equivalent command line is displayed in the interface — under the ▶ Generate the SBOM button and as the first entry of the progress log.

Settings are automatically saved between sessions.
