12. Trivy tab — Vulnerability analysis

The Trivy tab uses Aqua Security’s tool. It offers additional options compared with OSV-Scanner and Grype.

  ┌───────────────────────────────────────────────────────────────────┐
  │  [ SBOM file ] [ Container image ]                                │
  │  SBOM file : [ /project/sbom.cdx.json           ] [Choose ▾]    │
  │                                                                   │
  │  Severities : [CRITICAL] [HIGH] [MEDIUM] [LOW] [UNKNOWN]         │
  │  [ ] --ignore-unfixed   [ ] --skip-db-update                     │
  │  trivy.yaml   : [                               ] [Choose ▾]    │
  │                                                      [Analyze]   │
  ├───────────────────────────────────────────────────────────────────┤
  │  ⚠ 4 vulnerability(ies): 1 CRITICAL, 3 HIGH                      │
  ├───────────────────────┬───────────────────────────────────────────┤
  │ [Vulnerabilities (4)] │ [Raw JSON]                                │
  └───────────────────────┴───────────────────────────────────────────┘

12.1. Version indicator

Same behavior as in the Grype tab (see Version indicator), applied to trivy. The badge is displayed at the top of the configuration panel as soon as the startup check is finished.

12.2. Requirements

trivy must be installed and reachable in the PATH (see Installing trivy (optional)).

12.3. Selecting the source to analyze

Same SBOM file / Container image toggle, same accepted formats in image mode (registry, local archive, OCI layout directory) as in the Grype tab (see Selecting the source to analyze), including the optional Platform field (--platform, e.g. linux/arm64).

In SBOM file mode, Trivy is launched through its trivy sbom subcommand; in Container image mode, through trivy image (a local archive or directory is then passed through --input, a registry reference as a direct argument).

Note
 On a CycloneDX/SPDX SBOM generated by sbom_generator with the syft backend, it is normal that the SBOM file mode finds a few more Java CVEs than the Container image mode on the same image — this is not a false positive of the SBOM, but an under-detection by the jar analyzer built into Trivy for jars without pom.properties (e.g. internal Red Hat rebuilds), which the syft cataloger detects through the file name where Trivy fails. See Remediation for the detail with real figures.

The Per layer option is available in image mode, as for Grype; in attribution mode, the layer reported by Trivy itself (Layer.DiffID) is used — see Per-layer analysis (“Container image” source).

12.4. Scan options

12.4.1. Severity filter (--severity)

Check one or more severities to restrict the analysis. If none is checked, all severities are analyzed.

Available levels: CRITICAL, HIGH, MEDIUM, LOW, UNKNOWN.

12.4.2. --ignore-unfixed

Only shows the vulnerabilities for which a fixed version is available. Equivalent to --only-fixed in Grype.

12.4.3. --skip-db-update

Prevents Trivy from updating its local database at startup. Useful in an offline environment or for fast repeated analyses when the database is already up to date.

12.4.4. Configuration file (trivy.yaml)

Path to a Trivy configuration file in YAML format. Lets you define ignore rules, proxies, private registries, etc.

This parameter is optional. The Choose button offers a .yaml / .yml filter or all files.

12.5. Equivalent command

In SBOM file mode, Trivy is launched with the arguments:

trivy sbom --format json --quiet \
  [--severity CRITICAL,HIGH,...] \
  [--ignore-unfixed] \
  [--skip-db-update] \
  [--config trivy.yaml] \
  /path/to/sbom.cdx.json

In Container image mode:

trivy image --format json --quiet \
  [--severity CRITICAL,HIGH,...] [--ignore-unfixed] [--skip-db-update] \
  [--config trivy.yaml] [--platform linux/arm64] \
  nginx:latest
# or, for a local archive/OCI directory:
trivy image --format json --quiet [...] --input /path/to/image.tar

12.6. Results

Same interface as the Grype and OSV-Scanner tabs: search bar + sort
CSV/AsciiDoc+PDF export, severity filters, merging of visual duplicates (×N badge, see [sec-vue-table]), then the list of vulnerabilities.

CSV export (⬇ button): columns Severity, CVE/ID, Package, Installed version, Fixed version, Title, Locations.

AsciiDoc + PDF export (⬥ button): same report as on the Grype/OSV-Scanner tabs (summary by severity + detailed table, automatic PDF conversion if asciidoctor-pdf is installed) — see [sec-vue-table].

The Title column corresponds to the Title field of the Trivy JSON (short description of the CVE). It appears as a subtitle of each entry in the list.

Date filter: same bar as the Grype tab (see [sec-vue-table]). The Published field corresponds to PublishedDate of the Trivy JSON, the Modified field to LastModifiedDate. The Apply option copies the filter to the Grype and OSV-Scanner tabs.
