== General architecture

The program follows a concurrent pipeline:

....

        ├─ yarn.lock     ─► YarnParser      (pure Dart, pre-expansion)
        ├─ pom.xml       ─► MavenParser     (pure Dart, pre-expansion)
        ├─ pubspec.lock  ─► PubspecParser   (pure Dart, pre-expansion)
        ├─ pubspec.yaml  ─► PubspecParser   (pure Dart, pre-expansion)

All generators work on `List<Package>` — the abstract class common
to `RpmPackage`, `WheelPackage`, `DebPackage` and `OciPackage`.
`WheelPackage` is also reused for Go, npm, yarn, Maven and
Dart/Flutter (`packageType='pub'`) via the `packageType` field.

== `lib/i18n.dart` — FR / EN localisation of messages

Every text meant for a human (console messages, `--help`, errors, readable
reports) exists in French and English. There is no key catalog: each message
is written inline with its two versions, as close as possible to where it is
used.

[source,dart]
----
import 'i18n.dart';

stderr.writeln(tr('Fichier introuvable : $path', 'File not found: $path'));
----

[cols="1,3", options="header"]
|===
|Member |Role

|`enum Lang { fr, en }`
|Supported languages.

|`currentLang` (getter/setter)
|Current language of messages (French by default). Set once at startup by
`initLang`; unit tests set it directly.

|`tr(fr, en)`
|Returns one or the other text according to `currentLang`.

|`plural(n, frOne, frMany, enOne, enMany)`
|Simple plural (in French 0 and 1 are singular, in English only 1 is).

|`langFromLocale(code)`
|`fr_FR.UTF-8` → `Lang.fr`, `en_US` → `Lang.en`, `C` / `POSIX` / unknown → `null`.

|`stripLangArg(args, onValue)`
|Removes `--lang <v>` / `--lang=<v>` from an argument list, wherever it is.

|`initLang(args, {env})`
|Priority `--lang` > `SBOM_LANG` > `LC_ALL` > `LC_MESSAGES` > `LANG` > French.
Returns the arguments without `--lang`. An invalid value stops the program
(exit code 1).
|===

`main()` calls `initLang` first, *before* the subcommand dispatch, so that
`--lang` works anywhere (`sbom_generator scan --lang en …`); the `--lang`
option is also declared in the `ArgParser` of the main command, but only to
appear in `--help` (the real parsing is done by `initLang`).

Rules for adding or changing a message:

* write the French and English text together (`tr('…', '…')`), keeping
  interpolations identical (`$path`, `${x.length}`); no concatenation of
  translated fragments — one `tr()` per complete sentence;
* *never translate* a text read by a program: the `SBOM written → …` line (parsed by
  the GUI, `sbom_runner.dart`), property names and values (`sbom_generator:*`),
  JSON keys, SARIF identifiers, and texts embedded in SBOMs that the GUI parses
  (layer description, see `gui/lib/models/layer_nav.dart`). The CRA JSON
  report is keyed by stable identifiers (`id`), whereas the labels (`field`,
  verdict, blockers) are translated;
* integration tests that run the CLI and check a message pass `--lang fr`
  (`'bin/sbom_generator.dart', '--lang', 'fr', …`) so as not to depend on the
  locale of the machine; unit tests set `currentLang` and restore it in
  `tearDown` (`test/unit/i18n_test.dart`, `test/unit/i18n_reports_test.dart`).

== `lib/models.dart` — Type hierarchy

=== Abstract class `Package`

Interface common to all package types. All generators and
`buildDependencies` work exclusively with this interface.

[source,dart]
----
abstract class Package {
  // Common fields
  String get name;
  String get version;
  String get license;
  String get url;
  String get summary;
  String get vendor;
  String get arch;
  String get sourceRef;
  List<PackageHash> get hashes;   // artifact hashes (often empty)
  List<String> get requires;
  List<String> get provides;

  // Computed identifiers
  String get fullVersion;   // displayable version
  String get purl;          // Package URL (purl-spec)
  String get bomRef;        // unique CycloneDX identifier
  String get spdxId;        // SPDX identifier (SPDXRef-…)
  String get packageType;   // 'rpm' | 'pypi' | 'source' | 'deb'
}
----

The library utility function `_safeId(String s)` replaces any
character outside `[a-zA-Z0-9._-]` with `-`. It is used in the
`bomRef` and `spdxId` implementations of all package types.

=== Cryptographic hashes — `PackageHash` and `lib/hash_utils.dart`

`PackageHash(alg, content)`: `alg` in CycloneDX format (`SHA-256`,
`SHA-512`, `SHA-1`, `MD5`, `SHA3-256`…), `content` lowercase hexadecimal.
`lib/hash_utils.dart` centralises the collection and accepts **only the
hexadecimal digest of a real artifact** (right length for the algorithm):

* `normalizeHashAlg` / `packageHash` — algorithm whitelist,
  hex validation; rejects `h1`, `Q1…`, `sha224`, truncated values;
* `packageHashFromDigestString` — `"<algo>:<hex>"` (Trivy's `Digest` field);
* `packageHashFromSri` — Subresource Integrity `"sha512-<base64>"`
  (npm/yarn) → hexadecimal;
* `hashesFromSyftMetadata` — `metadata.archiveDigests` / `digests` / `digest`
  of a Syft artifact;
* `hashesFromCycloneDx` — `hashes` array of a cdxgen component;
* `hashLocalFile` — SHA-256 + SHA-512 of a local file (`package:crypto`);
* `spdx2Alg` / `spdx3Alg` — conversion of the labels to `SHA256` /
  `sha256` / `sha3_256`.

Populated by: `npm_parser`, `yarn_parser` (v1), `pubspec_parser`,
`deb_parser` / `jar_parser` / `wheel_parser` (direct file input),
`rpm_parser` (`.rpm` file → SHA-256/512; installed package → `%{SIGMD5}`
as `MD5`), `oci_parser` (Syft, Trivy, cdxgen paths). `RpmPackage` also carries
`headerSha256` (`%{SHA256HEADER}` — hash of the RPM *header*, not of the
`.rpm` file), emitted as the `rpm:header-sha256` property/annotation.

Emitted by the three generators (CycloneDX `hashes`, SPDX 2.3 `checksums`,
SPDX 3.0 `verifiedUsing`) and re-read by `sbom_reader` during a `convert`.

NOTE: For an SBOM coming from an *OCI image*, most system packages
remain without a hash (installed in the image, no artifact to hash;
neither Syft nor Trivy systematically reconstructs the `Digest`). The
"RPM list" path queries `%{SIGMD5}` directly and therefore covers all
installed packages.

== `lib/rpm_parser.dart` — RPM queries

=== `_queryFormat` constant

[source,dart]
----
static const _queryFormat =
    r'%{NAME}|%{VERSION}|%{RELEASE}|%{ARCH}|%{EPOCH}|%{LICENSE}|%{VENDOR}|%{URL}|%{BUILDTIME}|%{SHA256HEADER}|%{SOURCERPM}|%{SIGMD5}|%{SUMMARY}\n';
----

`SUMMARY` is last because it may contain `|`. The parser rejoins all
fragments ≥ index 12 in case of an excess split.

Hashes:

* `%{SHA256HEADER}` → `RpmPackage.headerSha256`, emitted as the
  `rpm:header-sha256` property (hash of the *header*, not of the file);
* `packageRef` = `.rpm` file → `hashLocalFile`: SHA-256 + SHA-512 of the
  file;
* otherwise (installed package) → `%{SIGMD5}` (RPM "pkgid": MD5 of header +
  payload), validated by `packageHash('MD5', …)` → `MD5` hash.

=== `parsePackage(String packageRef)`

The three `rpm` calls are launched *in parallel* via `Future.wait`:

[source,dart]
----
final results = await Future.wait([
  Process.run('rpm', [qFlag, '--queryformat', _queryFormat, packageRef]),
  Process.run('rpm', [qFlag, '--requires', packageRef]),
  Process.run('rpm', [qFlag, '--provides', packageRef]),
]);
----

. `rpm -q[p] --queryformat ...` → 13 metadata fields
. `rpm -q[p] --requires` → list of required capabilities (parsed by `_parseCapabilities`)
. `rpm -q[p] --provides` → list of provided capabilities (parsed by `_parseCapabilities`)

Returns `null` with a warning on `stderr` if the first call fails.

=== `_parseCapabilities(ProcessResult result)` _(new)_

Synchronous method replacing the former asynchronous `_queryCapabilities`.
Takes an already available `ProcessResult` and returns `List<String>` (empty if `exitCode != 0`).

=== `buildDependencies(List<Package> packages)`

Accepts a mixed RPM + Python list. The algorithm works in two passes.

*Pass 1 — building `providesMap`*

....
providesMap : capability name → bomRef
....

For each package: the package `name` + each `provides` entry are
added. Python packages include their normalised name in `provides`, which
allows intra-Python resolution.

*Pass 2 — resolving `requires`*

Each `requires` entry is normalised via `_capabilityName()` then looked up
in `providesMap`. A dependency is only added if the target is in the
list (`knownRefs`).

[source,dart]

return capability.split(RegExp(r'\s+[<>=!]'))[0].trim();

== `lib/wheel_parser.dart` — Reading Python wheels

=== How it works

The wheel is a ZIP containing a `{name}-{version}.dist-info/METADATA` directory.
The class uses `python3 zipfile` to extract this file without unzipping the
whole archive.

[source,python]
----
z = zipfile.ZipFile(sys.argv[1])
name = next(x for x in z.namelist() if x.endswith('/METADATA'))
sys.stdout.buffer.write(z.read(name))
----

=== `parseWheelFile(String path)`

Calls python3, gets the METADATA text, delegates to `_buildPackage()`.

=== `parseMetadataText(String sourceRef, String text, {String packageType})`

*Public extension point* used by `TarParser` to reuse the RFC 822 parser
without duplicating code. Makes it possible to build a `WheelPackage` from
an already extracted text.

=== RFC 822 parsing (`_parseRfc822`)

Returns `Map<String, List<String>>`: lowercase key → list of values.
Continuation lines (indented) are concatenated.

=== Extraction of key fields

[cols="1,1,2", options="header"]
|===
|METADATA field |Priority |Fallback

|License
|`License-Expression` (PEP 639)
|`License` → classifiers `License :: OSI Approved :: …`

|URL
|`Project-URL: Homepage, …`
|`Home-page`

|Vendor
|`Author-email` (strip `<addr>`)
|`Author` → `Maintainer`

|Arch
|last `-` segment before `.whl`
|`any`

|Requires
|`Requires-Dist` (strip constraints and markers)
|—
|===

=== Normalisation of `Requires-Dist`

[source,dart]
----
// "requests (>=2.0) ; extra == 'test'" → "requests"
var s = req.split(';').first.trim();
s = s.split(RegExp(r'[\s(]')).first.trim();
return _normalizePyName(s);  // lowercase + [-_.]+ → -

=== Python dependency resolution

`WheelPackage.provides = [normalizedName]` (PEP 503 normalised name).
`buildDependencies` also adds `pkg.name` to `providesMap`, covering both
the raw name and the normalised name.

== `lib/tar_parser.dart` — Reading tar archives

=== Embedded Python script

The script is run via `python3 -c` and returns a JSON object on stdout:

[source,json]
----
{"type": "python", "content": "<RFC 822 text>"}
----

or

[source,json]
----
{"type": "generic", "licenseFile": "LICENSE", "license": "<2 KB of the file>"}
----

*Detection logic* (in this order):

. Looks for `*.dist-info/METADATA` or `**/PKG-INFO` → type `python`
. Looks for `LICENSE`, `COPYING`, `LICENSE-*`, `LICENCE`, `COPYING.*` at depth ≤ 2
  → type `generic` with the content of the first file found (sorted by depth then length)

=== Python sdist case

If `type == 'python'`: delegates to `WheelParser().parseMetadataText(path, content)`
→ returns a `WheelPackage` with `packageType='pypi'`.

=== Generic archive case

If `type == 'generic'`: delegates to `buildGenericArchivePackage()` (from `archive_helpers.dart`):

. Analyses the file name via `parseArchiveFilename()`
. Identifies the license via `identifyArchiveLicense()`
. Returns a `WheelPackage` with `packageType='source'`

[NOTE]
====
These functions are now in `lib/archive_helpers.dart` (shared with
`ZipParser`). The logic is identical to the former private implementation of `TarParser`.
====

=== File name parsing (`parseArchiveFilename` in archive_helpers)

*Algorithm:*

. Remove the extension (`.tar.gz`, `.tgz`, `.tar`)
. Split on `-`
. Find the index of the first segment matching `^\d+\.\d+` (semantic version)
. *Name* = segments before the version, minus the platform keywords
. *Version* = the version segment
. *Arch* = first segment recognised as an architecture

*Keywords filtered out of the name* (`_isPlatformSegment`):

* OS: `linux`, `windows`, `darwin`, `macos`, `win`, `osx`
* Arch: `x86_64`, `x64`, `amd64`, `arm64`, `aarch64`, `i386`, `i686`
* Misc: `systemd`, `community`, `enterprise`
* Distros (regex): `rhel8`, `rhel88`, `el9`, `fc40`, `centos7`, `ubuntu22`, …

=== License identification (`identifyArchiveLicense` in archive_helpers)

Works on the first 2,000 characters of the license file.
Uses two zones:

* *`title`* (first 300 chars) for the GPL/LGPL families — avoids the false positive:
  GPL-2.0 mentions "GNU Library General Public License" in its body, but
  not in its title.
* *`lower`* (2,000 chars) for Apache, MIT, SSPL, MPL, etc.

Recognised licenses: `SSPL-1.0`, `Apache-2.0`, `Apache-1.1`, `GPL-2.0-only`,
`GPL-3.0-only`, `LGPL-2.0-only`, `LGPL-2.1-only`, `LGPL-3.0-only`, `MPL-2.0`,

== `lib/license_normalizer.dart` — Centralised SPDX normalisation

Factorisation of the license normalisation logic that used to be
buried in `cyclonedx_generator.dart`. Now imported by the three
generators (CycloneDX 1.6, SPDX 2.3, SPDX 3.0).

=== `LicenseNormalizer` (all methods `static`)

[cols="2,1,2", options="header"]
|===
|Method |Returns |Usage

|`toSpdxExpression(String raw)`
|`String`
|SPDX expression for SPDX 2.3 / 3.0

|`toCycloneDxLicenses(String raw)`
|`List<Map<String, dynamic>>`
|CycloneDX 1.6 `licenses[]` structure
|===

=== Common algorithm

. Empty / `(none)` case → returns empty
. Normalisation of boolean operators (`and` → `AND`, `or` → `OR`, `with` → `WITH`)
  with lookbehind/lookahead `\S` regexes to protect glued tokens
  (`GPL-2.0-or-later` unaltered)
. Detection of a compound expression (presence of `AND`/`OR`/`WITH` surrounded by spaces)
. Token-by-token resolution in `_sortedEntries` (sorted by decreasing length →
  avoids short matches before long ones)
. Choice of the CycloneDX field: `expression` (compound); otherwise `id` **if and
  only if** the token is in `kSpdxLicenseIds` (`lib/spdx_license_ids.dart`)
  or is a verified target of `_rpmToSpdx`; otherwise `name`. `LicenseRef-*` always goes
  to `name` (outside the SPDX enumeration of the CycloneDX schema).

[WARNING]
====
Never restore the former heuristic "the token contains a hyphen+digit
→ `id`": it let the `debian/copyright` shortcuts through as `license.id`
(`GFDL-NIV-1.3`, `BSD-3-clause-Berkeley`, `GPL-2.0-only+-with-link-exception`…),
producing a CycloneDX SBOM rejected by schema validation (id outside the SPDX
enumeration). The `id` field is now guarded by
`_isSpdxLicenseId()` → `isSpdxLicenseId()` (exact, case-sensitive membership
in `kSpdxLicenseIds`).
====

`lib/spdx_license_ids.dart` is a frozen snapshot of the SPDX License List 3.x
(license identifiers + exceptions). A genuinely SPDX id missing from the
snapshot degrades cleanly to `name` / `LicenseRef-…` (always
schema-valid) — the list is therefore deliberately broad without aiming
at exhaustiveness. `curl` is deliberately removed from it: `debian/copyright` uses it
as a vague name, we keep it as free text.

[TIP]
====
`_sortedEntries` is `static final` — computed only once when the
class is loaded. The old code re-sorted the table on every call of `_normaliseExpressionTokens`.
====

== `lib/jar_parser.dart` — Maven coordinates of a standalone `.jar`

Unlike `MavenParser` (which reads a `pom.xml` manifest), `JarParser` extracts the
Maven coordinates directly from a binary `.jar` archive, mirroring the logic already
used for OCI image scanning in `oci_parser.dart` (`_parseMavenJars` below),
but returns `WheelPackage(packageType: 'maven')` (like `maven_parser.dart`) rather
than `OciPackage` — no notion of `imageRef` for a local file.

*A `.jar` can produce several packages.* A "shaded"/uber-jar (e.g.
`netty-common-*.jar`) may embed, in addition to its own `pom.properties`, that of one
or more relocated dependencies (e.g. `org.jctools:jctools-core`). `parseJarFile`
therefore returns a *list*: the jar itself as the first element (if its identity could be
determined), followed by one element per embedded dependency detected — same behaviour as
syft, which lists each `pom.properties` found separately (with a `virtualPath` such as
`/netty-common-*.jar:org.jctools:jctools-core`).

=== `JarParser`

[source,dart]
----
class JarParser {
  Future<List<WheelPackage>> parseJarFile(String path) async { … }
  Future<List<(String, String, String)>> _readAllPomProperties(String path) async { … }
  Future<(String, String, String)?> _readSinglePomProperties(String path, String entryPath) async { … }
  Future<String?> _groupIdFromManifest(String path) async { … }
  bool _looksLikeGroupId(String s) => s.contains('.') && s == s.toLowerCase() && !s.contains(' ');
}
----

=== Resolution of own identity + embedded dependencies

. `_readAllPomProperties` lists *all* the
  `META-INF/maven/<groupId>/<artifactId>/pom.properties` present in
  the archive (`unzip -l` then one `unzip -p <jar> <exact path>` *per entry*,
  never a glob concatenating several blocks — see the bug below) and
  returns one `(groupId, artifactId, version)` per usable entry.
. Among these entries, the one whose `artifactId` matches the jar's file name
  (prefix before the first `-<digit>`) is the jar's *own* identity;
  if there is only one entry in total, it is taken by default.
  All the *other* entries become additional packages
  (relocated dependencies).
. If no entry matches the file name (ambiguous jar, several
  `pom.properties` with no clear match), the own identity falls back to
  the naming convention `<groupId>.<artifactId>-<version>.jar` (Quarkus/Red
  Hat), then to `META-INF/MANIFEST.MF` (`Bundle-SymbolicName`,
  `Implementation-Vendor-Id`, `Implementation-Title`,
  `Automatic-Module-Name`, in that order — first occurrence of each
  key kept, RFC 822 line folding handled, value retained only
  if `_looksLikeGroupId` accepts it: at least one dot, entirely
  lowercase — rejects e.g. `javafx.baseEmpty`).
+
*Discovered by comparison with syft on a real set of 207 jars*: this
behaviour reproduces it exactly for almost all the cases tested
(e.g. `caffeine` → `com.github.ben-manes.caffeine` via `Bundle-SymbolicName`,
`commons-httpclient` → `org.apache` via `Implementation-Vendor-Id`
taking priority over `Implementation-Title`). The `pom.properties` entries already
identified as embedded dependencies are still reported even in this case.
. If the manifest yields nothing usable either, `groupId` takes the
  value of `artifactId` (`pkg:maven/<artifactId>/<artifactId>@<version>`) —
  degraded but *not abandoned*.
. Empty list (+ `stderr` warning) only if neither own identity nor embedded
  dependency could be determined (no usable `pom.properties`
  and no recognisable version suffix in the file
  name).

*Bug fixed, discovered on a real jar* (`netty-common-4.1.100.Final.jar`):
reading the `pom.properties` through a broad glob
(`META-INF/maven/*/*/pom.properties`) without discrimination concatenates the
content of all the entries found, and a naive key=value parsing gets
overwritten by the second block — the `netty-common` jar came out with the
`jctools-core` identity! Same cause on `woodstox-core-6.5.1.jar`
(embeds `isorelax` and `net.java.dev.msv:xsdlib`). Reading each entry
*individually* (step 1 above) completely eliminates the risk of
mix-up, while allowing them to be correctly reported as separate packages
rather than arbitrarily choosing which one to keep.

=== `_knownGroupIdOverrides` — curated mappings (Spring Framework)

Some very widespread libraries (the "core" modules of Spring Framework:
`spring-core`, `spring-beans`, `spring-webmvc`, …) do not expose their real groupId
(`org.springframework`) anywhere in the jar itself — neither `pom.properties` nor a reliable
manifest field: only an `Automatic-Module-Name` such as `spring.core` is present, which
passes `_looksLikeGroupId` (dot, lowercase) but is a JPMS module name, not the real
Maven groupId.

*Concrete consequence, not merely cosmetic*: a vulnerability scanner (grype…)
associates CVEs with the real Maven coordinates. With `pkg:maven/spring.core/spring-core@…`
instead of `pkg:maven/org.springframework/spring-core@…`, no match is
found — real unfixed CVEs (e.g. CVE-2025-41249, CVE-2024-38820,
CVE-2025-22233, all on `org.springframework:spring-core`) remained invisible.
Detected by comparing a vulnerability scan on our SBOMs vs those of syft.

`_knownGroupIdOverrides` (`Map<String artifactId, String groupId>`) is checked *before*
the manifest heuristic — it must win against a misleading manifest value.
Deliberately limited to the ~22 official Spring Framework modules (stable list,
`org.springframework` groupId only): it is not an attempt to replicate a full
CPE dictionary like syft's, only to fill this precise gap, with a
direct security impact. Spring Data/Integration/Retry/Security are not in it: their
manifest already exposes the real groupId via `Implementation-Vendor-Id`.

Requires `unzip` in the PATH (check in `bin/sbom_generator.dart`,
`hasJar` → `unzip -v`).

[[sec-syft-binary]]
==== Analysing a standalone binary (`OciRefType.binary`, see `--binary`)

`syft <path> --output json` works on a standalone binary because
*syft itself detects* that an argument matching an existing local file
is a *file* source (not an image to resolve/pull), and applies its
binary catalogers to it:

* *Go* — `go-module-binary-cataloger` reads the `buildinfo` metadata
  embedded in the executable (those of `go version -m`) and recovers the
  complete list of modules + versions, whether the binary is statically
  linked or not, even stripped (as long as the build has not
  explicitly removed this section).
* *Other languages* — only syft's generic classifier applies: it
  recognises, by version-string fingerprint, a *fixed* catalog of
  well-known open source libraries (OpenSSL, zlib, sqlite, busybox…).

No `sbom_generator` code implements this extraction — it is
entirely delegated to syft; `_parseSyft` only passes the
path as is here. A statically linked library with no known signature
nor embedded metadata (home-grown C/C++, Rust without
`cargo-auditable`) cannot be recovered after the fact.

Syft licenses are `{spdxExpression, value}` objects — `spdxExpression`
is preferred if non-empty, otherwise `value`. Several licenses are joined by
`' AND '`.

The component's `vendor`, `arch`, `summary` and `url` are read via
`_firstNonEmpty(metadata, [...])`: syft cataloguers do not use the
same case depending on the ecosystem (dpkg/apk expose `architecture` / `maintainer`
in lowercase, rpm `arch` / `vendor`). The dpkg/apk maintainer is used as the
component `supplier` failing an rpm `vendor` field — without it, the SBOM
has no component supplier (sbomqs `comp_with_supplier` metric).

[[sec-syft-source-pkg]]
==== Source packages (`_syftSourcePackage`)

OSV.dev indexes Debian/Ubuntu advisories by *source* package (`zlib`, `perl`,
`sqlite3`), not by binary package (`zlib1g`, `perl-base`, `libsqlite3-0`).
syft only catalogues the binary, adding a PURL qualifier
`upstream=<source>` — which OSV-Scanner (scalibr) cannot use: on a
raw syft SBOM, OSV-Scanner therefore matches almost no system package
(19 CVEs on `haproxy:3.4.4`, against 58 with a cdxgen SBOM).

`_parseSyft` therefore emits, in addition to the binaries, one component per
distinct source package: `_syftSourcePackage()` reads `metadata.source` / `metadata.sourceVersion`
of the artifact, derives the source PURL from the normalised binary PURL (replacing
the name and version, removing `upstream=`), and deduplicates by source
name. A source is not emitted if a component already bears that name (case
of binary `perl` + `perl-base`, both of source `perl`).

Corollary: `_syftArtifactToPackage` removes `upstream=` from the binary's PURL
as soon as `metadata.source` differs from the name. Otherwise Grype would resolve binary→source
*and* match the explicit source component → same CVE counted twice
(224 raw matches instead of 80, 68 duplicate CVEs). cdxgen, which
does not emit `upstream=`, does not double count — we align with it. The set
of *unique* CVEs reported by Grype is identical before/after (checked):
only the over-counting of a CVE on each binary of a given source disappears.

[[sec-syft-debian-purl]]
==== Normalisation of the Debian `distro` qualifier (`_normalizeSyftSystemPurl`)

For Debian, syft fills the `distro` qualifier of system PURLs and the root
field `distro.versionID` with the *point release* read from
`/etc/debian_version` (e.g. `debian-13.6`), and not the major `13` carried by
`VERSION_ID` of `/etc/os-release`. Grype tolerates this form (it only keeps
the major), but OSV-Scanner in "SBOM scan" mode (scalibr) only links a
`pkg:deb/debian/...` to the `Debian:13` ecosystem if `distro` is
`debian-<major>` **or** if `distro_name` carries a known codename — with
`debian-13.6` it *silently* finds nothing (0 CVEs, no error).

`_normalizeSyftSystemPurl()` therefore brings `distro=debian-X.Y` back to
`distro=debian-X` and adds `distro_name=<codename>` (taken from
`distro.versionCodename` provided by syft), aligning with what cdxgen produces.
`_syftDistroToOsInfo()` applies the same truncation to the major for the
`operating-system` component. Processing limited to `id == debian`: for
alpine (`3.20.3`), rhel (`9.6`)… the minor carries information and is left
intact. Checked on `haproxy:3.4.4` (Debian 13.6): without the fix,
OSV-Scanner reported 0 CVEs where Grype saw 163 (all `wont-fix` /
`not-fixed`, no fixed version); with it, the three scanners cross-check.

=== Trivy backend (`_parseTrivy`)

Reads `Results[].Type` (e.g. `debian`, `centos`, `pip`) and normalises it via
`_normalizeTrivyType()` to the `packageType` ecosystems (`deb`, `rpm`,
`pypi`, etc.). The PURL is read from `Identifier.PURL` (trivy ≥ 0.38).

`trivy image` (the only mode invoked here) does not support the analysis of a
standalone binary — passing an `OciRefType.binary` to this backend would transmit
the path as is (`registry`/`binary` branch of the `switch`) and fail
on the trivy side. This is why `--binary` (see <<sec-option-binary>>) rejects
any `--oci-tool` other than `syft`.

[[sec-osinfo-oci-parser]]
=== `OsInfo` — base OS (`_syftDistroToOsInfo` / `_trivyMetadataToOsInfo` / `_cdxgenOsInfo`)

`OciParser` extracts the image's base OS (see the `OsInfo` class under
<<sec-models>>) to allow
`CycloneDxGenerator`/`SpdxGenerator`/`Spdx3Generator` to generate a dedicated
`operating-system` component in the SBOM. Without it, a consumer
such as Trivy in `trivy sbom` mode silently ignores the whole class of
"os-pkgs" vulnerabilities (RPM/DEB/APK system packages), even though each
package already carries `distro=...` in its own purl — see the CHANGELOG
for the detail of this bug, discovered on a real Keycloak image (101 `os-pkgs`
CVEs missing out of 253 when the SBOM was used instead of the direct
image).

Two undocumented Trivy requirements, empirically isolated by
bisection on a real SBOM (cf. `pkg/fanal/analyzer/os/release/release.go`
of the aquasecurity/trivy repository, function `idToOSFamily`, for the
reference table):

* The `name`/`id` field of the OS component must follow Trivy's internal
  taxonomy (`redhat`, `oracle`, `alma`…), not the `/etc/os-release` `id` that syft
  exposes as is (`rhel`, `ol`, `almalinux`…). `_toTrivyOsFamily()` translates
  via the `_trivyOsFamilyById` table; missing identifiers (`debian`,
  `ubuntu`…) are already identical to the expected Trivy family and pass
  unchanged. The trivy backend does not need this translation:
  `Metadata.OS.Family` is already in Trivy's internal taxonomy.
* On the SPDX 2.3 side, the OS package's `SPDXID` must be prefixed
  `SPDXRef-OperatingSystem-` (not `SPDXRef-Package-`) for Trivy to
  recognise it — `primaryPackagePurpose: "OPERATING-SYSTEM"` alone is not
  enough, empirically checked (see <<sec-spdx-generator>>).

`os: null` when syft/trivy detected no OS base (`scratch`
or distroless image), or for the skopeo backend (never covered, see above).

The cdxgen backend does not emit an `operating-system` component: `_cdxgenOsInfo()`
reconstructs the `OsInfo` from the `distro=` qualifier of a system package PURL
(e.g. `pkg:deb/debian/adduser@3.134?...&distro=debian-12` →
`id: debian, version: 12`), splitting the version at the last `-` and
applying `_toTrivyOsFamily()` to the identifier. `os: null` if no system
package carries a `distro` qualifier (image without a recognised OS base).

=== cdxgen backend (`_parseCdxgen`)

`cdxgen --type docker` accepts the three `OciRefType`s (registry reference,
`.tar` archive via absolute path, OCI layout directory). The CycloneDX BOM
is read on `stdout` (`--output -`) then normalised:

* `_cdxgenComponentToPackage()` discards components of type `file`,
  `cryptographic-asset`, `data`, `operating-system`, `container`, `platform`,
  then requires a PURL whose ecosystem prefix is in
  `_cdxgenPurlEcosystem` (`deb`, `rpm`, `apk`, `pypi`, `npm`, `golang`,
  `maven`, `gem`, `cargo`, `nuget`, `composer`, `pub`, `hex`, `conan`,
  `swift`). `pkg:generic` components (cdxgen's file-by-file inventory, APT
  repositories) are therefore rejected.
* cdxgen's PURL is kept as is in `purlOverride` (it includes
  `distro=`/`arch=`, needed by grype).
* For a `pkg:maven` component, `group` + `name` are recombined as
  `groupId:artifactId` (internal convention of `WheelPackage`/`OciPackage`).
* Licenses in CycloneDX format (`[{expression}]` or `[{license:{id|name}}]`).

=== Skopeo backend (`_parseSkopeo`)

*Phases:*

. `skopeo copy <src> oci:<tmpDir>:image` (unless `ociLayout` is already present)
. `_extractOciLayers()`: reads `index.json` → first manifest → list of
  layers → sequential `tar --extract` into `rootfs/`
. Detection of the installed package database:
  ** `var/lib/dpkg/status` → `_parseDpkgStatus()` (RFC 822 line by line)
  ** `var/lib/rpm` → `_parseRpmRoot()` (`rpm --root <dir> -qa --queryformat …`)
  ** `lib/apk/db/installed` → `_parseApkInstalled()` (APK key:value format)
. Detection of application packages in the rootfs:
  ** `_parseMavenJars(rootDir)`: looks for `*.jar` throughout the rootfs, extracts
     `META-INF/maven/*/*/pom.properties` via `unzip -p`, rebuilds the PURL
     `pkg:maven/<groupId>/<artifactId>@<version>`. Fallback: file name parsing
     with the Quarkus/Red Hat convention (`<groupId>.<artifactId>-<ver>.jar`).
     Deduplication by `groupId:artifactId:version`.
  ** `_parsePythonPackages(rootDir)`: looks for `*.dist-info/METADATA` and
     `*.egg-info/PKG-INFO` via `find`, parses the RFC 822 headers up to the
     first blank line. Fields extracted: `Name`, `Version`, `Summary`,
     `License`, `Home-page`. PURL `pkg:pypi/<name>@<version>`.
  ** `_parseNpmPackages(rootDir)`: looks for `node_modules/*/package.json`
     (first level only, ignores nested `node_modules`). Skips
     packages with `"private": true`. PURL `pkg:npm/<name>@<version>`.
. Deletion of the temporary directory (`chmod -R u+rwX` before `rm -rf`
  for files with restrictive permissions in some layers)

[NOTE]
====
Only packages with `installed` status in `dpkg/status` are included.
The `gpg-pubkey` entries of the RPM registry are ignored.
The 44 packages that syft finds in addition to skopeo (for Keycloak 26) come
from syft's reading of `MANIFEST.MF`, which produces non-standard heuristic
groupIds (`common/`, `jrt-fs/`, etc.). This gap is documented and accepted.
====

[[sec-nested-archive]]
== `lib/nested_archive.dart` — Descending into nested objects (`--depth`)

For a root object of `--input` (rpm, deb, jar/war/ear, wheel, zip, tar,
tgz), `NestedExplorer.explore(path, rootPrimaryRef:)` *selectively* extracts
the analysable objects from it, analyses them with the existing parsers,
then descends down to `maxDepth` (`parseNestedDepth`: integer ≥ 0
or `all` → `maxNestedDepth` = 10).

* *Extraction* (`_extractScript`, embedded Python script run by
  `python3`): detection by signature — rpm (lead + two headers + cpio newc
  gz/xz/bz2/zstd payload, read without `rpm2cpio`/`cpio`), deb (`ar` archive
  → `data.tar.*`), zip/jar/war/whl, tar. Only keeps
  "analysable" files (archive/package extensions and manifests outside
  `META-INF/`). Safeguards: 4 GiB in total, 2 GiB per file, 50,000
  files; absolute paths or paths leaving the destination and links ignored;
  a limit being reached truncates the extraction (warning, not an error).
  zstd goes through the `zstd` CLI (absent from Python's standard module < 3.14).
* *Traversal* (`_walk`): one temporary directory per archive, deleted after
  its children have been traversed (disk space bounded by the depth). Each
  file is typed by `_kindOf` (`archive`: descent possible;
  `manifest`: analysed without descent). Packages receive a *logical*
  `sourceRef` `root!/path!/path` via `Package.copyWith(sourceRef:)`
  (never the temporary path).
* *`NestedObject`*: `location`, `depth`, `packages` (the first is the
  object's main component — `parseJarFile` returns the jar itself first,
  then the relocated dependencies —, `primary`), `parentRef`
  (`bomRef` of the container's main component).
* *Graph*: `withNestedDependencies` adds the edges container →
  object's main component → its other components; a manifest
  (without a main component) is attached to the container. `main()` keeps
  only the edges whose two ends survive the deduplication.
* *Annotations*: `nestedFields(pkg)` (`location`, `depth`, empty if
  `sourceRef` does not contain `!/`) is consumed by the CycloneDX
  generators (`sbom_generator:nested:*` properties), SPDX 2.3 / 3.0
  (annotation) and custom JSON (`nested`). The tabular formats
  (CSV, Markdown, AsciiDoc, HTML) do not carry the column.
* *Per-object files*: after the global one, `main()` writes one SBOM per
  `NestedObject` (`nestedFileBase` → `<base>.nested-NN-<slug>`, `writeAll(…,
  docNameOverride:)`) unless `--no-nested-files`. License/supplier overrides
  and cosign signature apply to them as to layer SBOMs.
* *Scan*: `scan --package` relaunches the CLI (`_runSelf`) with
  `-i <file> --depth N --no-nested-files -f cyclonedx`, then
  `NestedSbomIndex.load` (`name@version` → `location`) and `attributeNested`
  set the `container` key on each finding (falling back to the name alone if it is
  unambiguous); `_printScanResults` adds the `OBJECT` column. Reports and SARIF
  do not use `container`.
* *CLI validation*: invalid `--depth` → error; `--depth > 0` without
  `--input` → error; `scan --depth` without `--package` → error; `--package`
  mutually exclusive with `--sbom`/`--image`.
* Tests: `test/unit/nested_archive_test.dart` (unit),
  `test/integration/nested_depth_test.dart` (tgz → jar → jar + lockfile,
  fixtures built with `python3`).

[[sec-image-layers]]
== `lib/image_layers.dart` — Per-layer analysis (`--per-layer`)

Produces, for a container image, the *delta* of each layer (added,
modified, removed components) and the annotations that the generators
add to the global SBOM and the layer SBOMs. Backend-independent:
the analysis of a rootfs state is injected (`scan`), and the attribution by
metadata is provided by `OciParser`.

=== Model

[cols="1,3",options="header"]
|===
|Type |Role

|`ImageLayer`
|layer: `index` (1 = base), `diffId` (`sha256:…` of the uncompressed tar), `blobPath` (tar on disk, rootfs mode), `createdBy`/`created` (config `history[]`, `empty_layer` entries ignored)

|`LayerDelta`
|`added`, `modified` (`PackageChange = (before, after)`), `removed`; `packages` = components described by the layer SBOM; `map(f)` to apply license / supplier overrides

|`LayerAnalysis`
|`mode`, `layers`, `deltas`; `origins()` → `bomRef` → `LayerOrigin` (introducing layer, modifying layers) for the final state

|`LayerSummary`
|summary of a layer (counters, `fileBase`, `documentUuid`) — serialised as JSON in the global SBOM

|`LayerAnnotations`
|what the generators receive (`layers:` parameter of each `generate`/`writeToFile`): `forLayer` (described layer, change per `bomRef`, previous version, removed ones, link to the global one) or `forGlobal` (originating layer per `bomRef`, layer summary). `documentUuid` fixes the CycloneDX serial number / the SPDX namespace, for cross-links
|===

=== Reading the layers

- `readDockerArchiveLayers(dir)`: extracted `docker save`/`podman save` archive
  (`manifest.json` → `Config` + `Layers[]`).
- `readOciLayoutLayers(dir)`: `index.json` → (nested index, `linux/amd64`
  manifest preferably) → config + `layers[]` (`blobs/sha256/…`).
- Without usable `diff_ids`, the digest is deduced from the file name.

=== `rootfs` mode: `analyzeRootfsLayers`

For each layer: `tar -xf` into a temporary directory (compression
detected by tar; entries that cannot be created without privileges ignored),
`chmod -R u+rwX`, then *`mergeLayerDir`* onto the cumulative rootfs, then
`scan(rootDir)` and `diffPackages(previous, current)`.

`mergeLayerDir` applies overlayfs semantics: `.wh.<name>` removes the lower
entry, `.wh..wh..opq` empties the directory, a directory merges recursively,
any other entry replaces. Entries are *moved* (`rename`) and the descent *never* goes
through a symbolic link — unlike successive `tar -x` into the same directory
(the historical `skopeo` backend), a malicious layer (`x -> /` then
`x/…`) cannot write anything outside the rootfs (case covered by
`test/unit/image_layers_test.dart`).

`diffPackages` first matches by `bomRef` (component present on both
sides: "modified" if PURL, license, supplier or hashes differ),
then the leftovers by logical identity `type|name|arch` when it is
unambiguous on both sides — a version bump becomes "modified" rather than
removal + addition. Several versions of the same name (nested `node_modules`)
are not paired.

=== `metadata` mode: `metadataLayerAnalysis`

Distributes the packages of the usual analysis according to `layerOf` (`bomRef` →
layer index) provided by `OciParser.layerAttribution`; only additions
are known. A package with no known layer appears in no layer SBOM
(console warning).

=== `OciParser` side

[cols="1,3",options="header"]
|===
|Method |Role

|`layerAttribution(ref, tool)`
|trivy: `Results[].Packages[].Layer.DiffID`, layers from `Metadata.DiffIDs` + `Metadata.ImageConfig.history`. syft: second `--scope all-layers` analysis; each artifact carries the `locations[].layerID` where syft saw it, the lowest layer is kept (the derived source package inherits that of its binary); layers from `source.metadata.layers[].digest`, history from `source.metadata.config` (base64). The usual "squashed" analysis is not suitable: it attaches all system packages to the last layer that rewrote the rpm/dpkg/apk database

|`rootfsLayerAnalysis(ref, tool)`
|`_materializeLayers` (tar archive — docker-archive or oci-archive —, OCI layout, or registry copied via `_copyToOciLayout`), then `analyzeRootfsLayers` with `scanRootfs`

|`scanRootfs(dir, tool, ref)`
|syft `dir:<dir> --base-path <dir> --override-default-catalogers image` (same "installed packages" catalogers as for an image; absolute links resolved under `dir`); trivy `rootfs`; skopeo `_scanExtractedRootfs` (dpkg/RPM/APK/Maven/Python/npm); cdxgen `--type rootfs`

|`_copyToOciLayout(ref, dest)`
|`skopeo copy` to `oci:<dest>:image`; for a registry reference, falls back to `containers-storage:` (podman) then `docker-daemon:` (locally built images)
|===

== `lib/sbom_diff.dart` — SBOM comparison

=== `SbomDiffer`

Main class. `diff()`, `printDiff()` and `toJson()` are instance
methods; only `loadFile()` is static:

[cols="2,2,2", options="header"]
|===
|Method |Input |Output

|`diff(Map a, Map b)`

=== `SbomDiffResult`

[source,dart]
----
class SbomDiffResult {
  final List<SbomComponent> added;
  final List<SbomComponent> removed;
  final List<SbomComponentUpdate> updated;
}
----

=== Comparison algorithm

. `_indexComponents()` detects the format of each file independently
  (`spdxVersion` present → `_indexSpdxComponents()`, `@graph` present →
  `_indexSpdx3Components()`, otherwise `_indexCycloneDxComponents()`) and produces
  a `Map<String, SbomComponent>` indexed by `_componentKey()`.
. `_componentKey()`: `purl.substring(0, purl.lastIndexOf('@'))` if the PURL
  contains an `@`, otherwise `name:type` (key without version) — identical for the
  three formats, which makes it possible to compare two files in different
  formats.
. Index comparison: absent from A = addition, absent from B = removal, present in
  both with a different version = update.

[NOTE]
====
The `diff` subcommand is accessible via `sbom_generator diff <a> <b> [--json] [-o <out>]`.
The same purl-first key is used on the GUI side (`gui/lib/widgets/sbom_diff_panel.dart`,
function `_diffKey()`) so that both comparisons produce the same result.
====

== `lib/sbom_merger.dart` — SBOM merging

=== `SbomMerger`

[source,dart]
----
class SbomMerger {
  Map<String, dynamic> merge(
    List<Map<String, dynamic>> sboms, {
    String? documentName,
  });
}
----

`merge()` is an instance method (not static). It detects the format
of the **first** SBOM provided (`spdxVersion` present → `_mergeSpdx()`, otherwise
`_mergeCycloneDx()`) and merges all the files according to that same
structure; the resulting document is produced in that same format.

=== Merge algorithm — CycloneDX (`_mergeCycloneDx`)

. First SBOM as the base (preserves `metadata`).
. Traversal of all the following SBOMs:
  - Deduplication of `components` by `purl` (then by `bom-ref` if the PURL is absent).
  - Deduplication of `dependencies` by `ref`.
  - Deduplication of `citations` and `definitions.patents` (CycloneDX 1.7) by `bom-ref`.
. New UUID v4 `serialNumber` generated via `_generateUuid()`.
. `documentName` overrides `metadata.component.name` if provided.

=== Merge algorithm — SPDX 2.3 (`_mergeSpdx`)

. First SBOM as the base (preserves `dataLicense`, `creationInfo.licenseListVersion`).
. Deduplication of `packages` by PURL (`externalRefs[referenceType=purl]`), then by `SPDXID`.
. Deduplication of `relationships` by triple `(spdxElementId, relationshipType, relatedSpdxElement)`.
. New `documentNamespace` generated via `_generateUuid()`.
. `documentName` overrides `name` if provided.

[NOTE]
====
The source files must all be in the same format as the first
file provided (CycloneDX or SPDX 2.3); a file in a different format
is not explicitly rejected — it simply produces an
incomplete merge, for lack of cross-format validation. The SPDX 3.0
format (JSON-LD) is not supported as input for `merge`.

The source documents' `SPDXID`s are kept as is in the merged
`relationships`; for SBOMs generated by this tool they are
deterministic (name+version via `Package.spdxId`), hence stable across
documents — a collision remains theoretically possible if an
external document reuses a generic `SPDXID` for another package.
====

== `lib/license_report_generator.dart` — License report (`licenses` subcommand)

=== `LicenseReportGenerator`

[source,dart]
----
enum LicenseReportFormat { asciidoc, markdown, html, csv, json }

class LicenseReportGenerator {
  LicenseReport analyze(List<Package> packages, {String? documentName});
  String render(List<Package> packages,
      {String? documentName, LicenseReportFormat format});
  Future<void> writeToFile(
    List<Package> packages,
    String outputPath, {
    String? documentName,
    LicenseReportFormat format,
  });
  static LicenseCategory classify(String license);
}
----

`analyze` produces a `LicenseReport` (sorted groups, packages without license,
counters and copyleft identifiers) independent of the format; each format
is only a rendering of this model. The JSON (`-f json`) is the contract read by the
GUI (`gui/lib/models/license_report.dart`): `summary`, `licenses[]`
(`license`, `category` = `permissive|weak-copyleft|strong-copyleft`,
`packages[]`) and `unknown[]`.

Groups packages by **exact** `pkg.license` — the string as
present in the source SBOM, including compound expressions
(`A AND B AND …`, frequent on Debian/RPM packages whose all
licenses found in the sources are concatenated) — and writes an
AsciiDoc report in four parts: numeric summary, copyleft warning, detailed
section per license, section of packages with no detected license.

=== Copyleft classification

`classify(license)` applies a substring heuristic on the whole
expression (case-insensitive):

[cols="2,3", options="header"]
|===
|Category |Condition

|`strongCopyleft`
|contains `AGPL`, or `GPL` not preceded by a letter — regex `(?<![A-Z])GPL`, so as not to confuse with `LGPL`

|`weakCopyleft`
|contains `LGPL`, `MPL`, `EPL`, `CDDL`, `CPL` or `EUPL`

|`permissive`
|none of the markers above

|`unknown`
|empty string
|===

This classification applies to the **whole** expression: a compound expression
containing a single copyleft token (e.g. `BSD-3-Clause AND
GPL-2.0-only AND MIT`) classifies the whole group as copyleft — this behaviour
is intended, the presence of a copyleft component in the mix is enough
to trigger the warning.

[NOTE]
====
`_copyleftTokens(license, target)` splits a compound expression on
`AND`/`OR` and only keeps the tokens whose *individual* classification
matches `target`. This step is only used to build the list
of identifiers of the warning at the top of the report — the grouping by
section always keeps the complete expression as declared.

Without this step, a real Debian SBOM (licenses systematically
concatenated) produces a warning listing dozens of entire
compound strings, unreadable, rather than the individual copyleft identifiers
actually at issue. Observed when testing the command on a Trivy SBOM
of 157 nginx/Debian packages: without the splitting, the warning
fit on a single line of several thousand characters.
====

The copyleft classification is a spotting heuristic meant to
draw attention, not a legal analysis.

== `lib/requirements_parser.dart` — Python requirements.txt parsing

*Pure Dart* parser, no subprocess. Returns `List<WheelPackage>`.

=== `RequirementsParser`

[source,dart]
----
class RequirementsParser {
  List<WheelPackage> parseFile(String path) { … }
  WheelPackage? _parseLine(String raw, String sourceRef) { … }
}
----

=== Ignored lines

* Empty or starting with `#`
* pip directives: `-r`, `-i`, `-e`, `-f`, `-c`

=== Per-line extraction

. Removes environment markers (`;` and what follows)
. Removes inline comments (`#` and what follows)
. Removes `[security]` extras (regex `\[.*?\]`)
. Extracts the version after `==` (pinned) or the first version number otherwise
. Normalises the name according to PEP 503 (`[-_.]+ → -`, lowercase)

=== Integration in `main()` — manifest pre-expansion

All parsers producing N packages from a single file (1:N cardinality)
are *pre-expanded before the concurrent loop*:

[source,dart]
----
for (final ref in packageRefs) {
  if (_isRequirements(ref)) {
    preloadedPackages.addAll(reqParser.parseFile(ref));
  } else if (_isGoSum(ref)) {
    preloadedPackages.addAll(goParser.parseGoSum(ref));
  } else if (_isGoMod(ref)) {
    preloadedPackages.addAll(goParser.parseGoMod(ref));
  } else if (_isPackageLock(ref)) {
    preloadedPackages.addAll(npmParser.parsePackageLock(ref));
  } else if (_isYarnLock(ref)) {
    preloadedPackages.addAll(yarnParser.parseYarnLock(ref));
  } else if (_isPomXml(ref)) {
    preloadedPackages.addAll(mavenParser.parsePomXml(ref));
  } else if (_isPubspecLock(ref)) {
    preloadedPackages.addAll(pubspecParser.parsePubspecLock(ref));
  } else if (_isPubspecYaml(ref)) {
    preloadedPackages.addAll(pubspecParser.parsePubspecYaml(ref));
  } else {
    filteredRefs.add(ref);
  }
}
// … Future.wait loop over filteredRefs …
packages.addAll(preloadedPackages);
----

Detection helpers:

[source,dart]
----
bool _isRequirements(String r) => r.endsWith('.txt') && !r.endsWith('.whl');
bool _isGoSum(String r)        => r.endsWith('go.sum');
bool _isGoMod(String r)        => r.endsWith('go.mod');
bool _isPackageLock(String r)  => r.endsWith('package-lock.json');
bool _isYarnLock(String r)     => r.endsWith('yarn.lock');
bool _isPomXml(String r)       => r.endsWith('pom.xml');
bool _isPubspecLock(String r)  => r.endsWith('pubspec.lock');
bool _isPubspecYaml(String r)  => r.endsWith('pubspec.yaml');
----

[NOTE]
====
*Why pre-expansion?* The concurrent loop produces `Future<Package?>`
(1 ref → 0 or 1 package). A manifest file may contain N packages
(1:N cardinality), incompatible with this model.
====

== `lib/go_parser.dart` — Go modules

Pure Dart parser for `go.sum` and `go.mod`. Uses `WheelPackage` with
`packageType: 'golang'`.

=== `parseGoSum(String path)`

`go.sum` format: a `module version hash` or `module version/go.mod hash` line.

[source,text]
----
github.com/gorilla/mux v1.8.1 h1:TnC2...
github.com/gorilla/mux v1.8.1/go.mod h1:dvbg...
----

Processing:
. Ignores empty lines or lines starting with `#`
. Ignores lines whose second field ends with `/go.mod` (checksum duplicate)
. Extracts `module` and `version` (`v` prefix removed)
. Deduplication by `module@version` key (avoids the duplicate between a module's two lines)
. Name = raw module path in lowercase (slashes kept for the PURL)

=== `parseGoMod(String path)`

`go.mod` format: individual or block `require` directives.

[source,text]
----
require (
    github.com/gorilla/mux v1.8.1
    golang.org/x/net v0.17.0  // indirect
)
require github.com/pkg/errors v0.9.1
----

Processing:
. Detects `require (…)` blocks and isolated `require x v` directives
. Removes `// indirect` comments and everything following `//`
. `v` prefix removed from the version
. `v0.0.0-yyyymmdd-commit` versions (pseudo-versions) are kept as is

== `lib/npm_parser.dart` — npm packages

Pure Dart parser for `package-lock.json` (lockfileVersion 1, 2 and 3).

=== Version detection

[source,dart]
----
final v = json['lockfileVersion'];
if (v == 1) return _parseDependenciesField(json);
return _parsePackagesField(json);   // v2 and v3
----

=== `_parsePackagesField` (v2/v3)

`packages` key → map `{ "node_modules/pkg": { version, license, integrity, … } }`.

. Ignores the empty key `""` (project root)
. `_stripNodeModulesPrefix`: segment after the *last* `node_modules/`
  (handles nested paths `node_modules/a/node_modules/b`)
. `_extractLicense(raw)`: handles `String | List` (some packages declare
  several licenses as an array `[{ "type": "MIT" }]`)
. `integrity` (SRI `sha512-<base64>`) → `hashes` via `packageHashFromSri`

==== Supplier (`_authorFromPackageJson`)

The npm lockfile carries **no author**. `_parsePackagesField` resolves
`<lockfile directory>/<node_modules key>/package.json` and reads `author`
(otherwise the 1^st^ `contributors[]` / `maintainers[]`); `_personName` normalises
a `{name}` object or a `"Name <email> (url)"` string → `"Name"`.
Best-effort: `node_modules` tree absent (lockfile committed without
`npm install`) → empty string, no error. Not applied to the v1 path
(no reliable installation path).

=== `_parseDependenciesField` (v1)

`dependencies` key → recursive map (nested dependencies).

. Recursive processing: for each package, its own `dependencies` are
  also parsed (npm v1 nested dependencies)
. Each package has `version` and `resolved` at the top level

== `lib/maven_parser.dart` — Maven dependencies

Pure Dart parser for `pom.xml`. Uses light regex-based XML extraction
(no XML library available — the only pubspec dependency: `args: ^2.4.2`).

=== Pre-cleaning

Before extraction, the confusing sections are removed from the XML:

[source,dart]
----
String _stripSection(String xml, String tag) =>
    xml.replaceAll(RegExp('<$tag[^>]*>.*?</$tag>', dotAll: true), '');

final cleaned = _stripSection(
    _stripSection(_stripSection(content, 'dependencyManagement'), 'build'),
    'plugin');
----

This avoids extracting dependencies from `dependencyManagement` (version
declarations without an actual dependency) and Maven plugins.

=== Dependency extraction

Regex on each `<dependency>…</dependency>` block:

. `_extractFirst(xml, 'groupId')` and `_extractFirst(xml, 'artifactId')` via regex
. Version extracted via `_extractFirst(xml, 'version')` (empty if a `${…}` variable)
. `test` or `system` scope → ignored
. Name stored as `groupId:artifactId` (`:` separator for PURL reconstruction)

=== Maven PURL

The `WheelPackage.purl` getter handles the `'maven'` type specifically:

[source,dart]
----
if (_packageType == 'maven') {
  final parts = name.split(':');  // ["org.slf4j", "slf4j-api"]
  final ns = Uri.encodeComponent(parts[0]);
  final nm = Uri.encodeComponent(parts[1]);
  return 'pkg:maven/$ns/$nm@$v';
}
----

Example: `org.slf4j:slf4j-api@2.0.7` → `pkg:maven/org.slf4j/slf4j-api@2.0.7`

== `lib/pubspec_parser.dart` — Dart/Flutter packages

*Pure Dart* parser (without the `yaml` dependency) for `pubspec.lock` and
`pubspec.yaml`. Returns `List<WheelPackage>` with `packageType: 'pub'`
(PURL `pkg:pub/<name>@<ver>`).

=== `parsePubspecLock(String path, {Map<String,String> sdkVersions})`

Line-by-line reading of the `packages:` block (stable 2-space indentation
generated by `pub`). For each package:

* `dependency:` — `direct dev` → **excluded**. Transitives pulled only
  by a dev dependency cannot be distinguished in the lockfile: they
  remain included.
* `source:` — `hosted` | `git` | `path` | `sdk`: all kept.
* `description.name` (hosted) → package name; otherwise the block key.
* `source: sdk` — the name is **always the key** (`flutter`, `sky_engine`,
  `flutter_web_plugins`…). The scalar `description:` (`description: flutter`)
  names the SDK, not the package: using it as the name stuck all these packages
  on `flutter` then deduplicated them (regression fixed). It is now only
  used to choose the key in `sdkVersions`.
* `version:` — resolved version; for `source: sdk`, `pub` always writes
  `"0.0.0"` (no real version for a package shipped in the SDK) → **empty
  version** (`pkg:pub/flutter`), unless `sdkVersions` provides the real version
  (`{'flutter': '3.47.2'}` → all `description: flutter` packages inherit
  `3.47.2`). Fed by `--sdk-version <sdk>=<ver>` on the CLI side.

`--sdk-version` has a **second effect**, independent of the pubspec parsing: the
`sdkVersions` map is passed to `CycloneDxGenerator` / `SpdxGenerator` /
`Spdx3Generator` (`sdkTools` parameter) which add each SDK to the document's
toolchain — `metadata.tools.components[]` (`type: platform`,
`bom-ref: tool-sdk-<name>`) in CycloneDX, `creationInfo.creators`
(`Tool: <name>-<version>`) in SPDX 2.3, a `Tool` element referenced by
`createdBy` in SPDX 3.0. This is the only place where the **dart** SDK version
appears (it has no package entry in a Flutter lockfile).

==== Licenses (`--pub-cache` / `--flutter-root`)

`pubspec.lock` carries no license. `_resolveLicense()` locates the
`LICENSE` file of the *resolved* package on disk and identifies it via
`identifyArchiveLicense()` (`archive_helpers.dart`):

[cols="1,3", options="header"]
|===
|`source:` |Directory searched

|`hosted`
|`<pubCache>/hosted/<host>/<name>-<version>/` (host deduced from `description.url`,
`pub.dev` by default)

|`git`
|`<pubCache>/git/<name>-<resolved-ref>[/<description.path>]/`

|`path`
|`<description.path>` resolved from the `pubspec.lock` directory

|`sdk`
|`<flutterRoot>/packages/<name>/`, then `<flutterRoot>/bin/cache/pkg/<name>/`,
then `<flutterRoot>/LICENSE` (fallback — `flutter_web_plugins` has no LICENSE
of its own)
|===

File names tested: `LICENSE`, `LICENSE.md`, `LICENSE.txt`, `LICENCE`,
`COPYING`, `license`. A missing or unidentifiable file → empty license, no
error. `pubCache` is auto-detected on the CLI side (`$PUB_CACHE`, otherwise
`~/.pub-cache` if it exists); `--pub-cache ""` neutralises it.

NOTE: `identifyArchiveLicense()` now recognises the canonical BSD-3-Clause
text ("Redistribution and use in source and binary forms… / endorse or
promote products derived") even without the word "BSD" — it is the `LICENSE` of
almost all pub packages (written by Google).
* `description.sha256` (hosted) → `WheelPackage.hashes` (`PackageHash('SHA-256', …)`).
* `description.url` → homepage (`https://pub.dev/packages/<name>` for
  pub.dev, `<registry>/packages/<name>` for a private registry, the repository
  URL for `git`).

=== `parsePubspecYaml(String path, {Map<String,String> sdkVersions})`

Only reads the `dependencies:` section (the `dev_dependencies:` and
`dependency_overrides:` sections are ignored). `flush()` approach: each dependency
block is buffered to spot a nested `sdk: <x>` line (SDK dependency)
before emission — its version then comes from `sdkVersions[<x>]` if provided,
otherwise empty. A simple constraint is reduced to a single version when it is
unambiguous (`^1.2.3`, `1.2.3`, `>=1.2.3` → `1.2.3`); a range
(`>=1.0.0 <2.0.0`) or `any` gives an empty version.

=== Lock / yaml priority

In a directory scan, if `pubspec.lock` and `pubspec.yaml` coexist in the
same place, `bin/sbom_generator.dart` only keeps the `.lock` (resolved
versions + transitive closure). In a list file, both are honoured as
listed.

== `bin/sbom_generator.dart` — Entry point

=== `--input` / `-i` option — list file, single archive, or directory

Historically, `--input` always had to point to a list file
(text, one reference per line). Passing a binary archive directly
(`.zip` in particular) crashed `File.readAsLines()` with a poorly explicit
UTF-8 decoding `FileSystemException`. `--input` now accepts
three forms, resolved by three mutually exclusive branches:

[source,dart]
----
bool _isSingleArchiveInput(String path) =>
    path.endsWith('.zip') ||
    _isTar(path) ||
    path.endsWith('.whl') ||
    path.endsWith('.deb') ||
    path.endsWith('.rpm') ||
    _isJar(path);

if (inputPath != null) {
  if (await FileSystemEntity.isDirectory(inputPath)) {
    // Recursive scan: any file matched by _isSupportedPackageFile()
    // becomes a packageRef.
    final found = <String>[];
    await for (final entity
        in Directory(inputPath).list(recursive: true, followLinks: false)) {
      if (entity is File && _isSupportedPackageFile(entity.path)) {
        found.add(entity.path);
      }
    }
    found.sort();
    // If pubspec.lock and pubspec.yaml coexist in the same place, only the
    // .lock is kept (resolved versions + transitive closure).
    packageRefs = found;
  } else if (_isSingleArchiveInput(inputPath) ||
      _isSupportedPackageFile(inputPath)) {
    // Single archive/package/manifest (exact name for manifests):
    // pubspec.lock, requirements.txt, go.sum, pom.xml…
    packageRefs = [inputPath];
  } else {
    try {
      lines = await File(inputPath).readAsLines();
    } on FileSystemException {
      _err('… explicit message …');
      exit(1);
    }
    // … splitting into packageRefs …
  }
}
----

For any remaining path (list file branch), the line-by-line reading
remains protected by a `try/catch`: any `FileSystemException` (unrecognised
binary file, invalid encoding) produces an actionable error message instead of a raw
stack trace.

`_isSupportedPackageFile()` is deliberately stricter than the list
file for manifests: it requires an *exact* file name
(`requirements.txt`, `pom.xml`, `go.sum`, `go.mod`, `package-lock.json`,
`yarn.lock`, `pubspec.lock`, `pubspec.yaml`) rather than a generic extension
(`*.txt` for instance), to avoid
a `README.txt` or a `notes.txt` lying around in the scanned tree being
mistaken for a requirements file. The list file, for its part, keeps
accepting any `.txt` (other than `.whl`) via `_isRequirements()` — the
tolerance is acceptable there because the user explicitly typed the path.

Bare RPM package names (e.g. `bash`) are never discovered by the
directory scan: they are not files on disk. `--rpm-dir` remains
the dedicated mechanism to resolve this case.

`FileSystemEntity.type()` replaces the former `File(inputPath).exists()` for
the initial existence check, because the latter returns `false` for a
directory path (only true for files), which would have made
`--input <directory>` fail with "Input file not found".

=== `--rpm-dir` / `-d` option

Makes it possible to resolve bare RPM names (without `/` or extension) to local
`.rpm` files instead of querying the installed packages database.

*Indexing at startup* (only once):

[source,dart]
----
final rpmExactIndex = <String, String>{};       // stem → absolute path
final rpmNameIndex  = <String, List<String>>{}; // package name → [sorted paths]

await for (final entity in dir.list(recursive: true, followLinks: false)) {
  if (entity is File && entity.path.endsWith('.rpm')) {
    final stem = entity.path.split('/').last.replaceAll(RegExp(r'\.rpm$'), '');
    rpmExactIndex[stem] = entity.path;
    final name = RegExp(r'^(.+?)-\d').firstMatch(stem)?.group(1) ?? stem;
    rpmNameIndex.putIfAbsent(name, () => []).add(entity.path);
  }
}
for (final paths in rpmNameIndex.values) paths.sort();
----

* *`rpmExactIndex`*: key = full stem (e.g. `bash-5.1.8-6.el9.x86_64`),
  value = path. Covers exact NEVRA matches.
* *`rpmNameIndex`*: key = package name extracted by `^(.+?)-\d` (e.g. `bash`),
  value = sorted list of paths. Covers short names.

*Resolution in the loop*:

[source,dart]
----
if (rpmDir != null && !ref.contains('/') && !ref.endsWith('.whl') && !_isTar(ref)) {
  final resolved = rpmExactIndex[ref] ?? rpmNameIndex[ref]?.first;
  if (resolved != null) ref = resolved;
  // If several files match the name: warning + first alphabetically
}
----

If no match is found in the directory, `rpm -q` is used
normally (transparent fallback). `.whl` references, tar/zip archives,
`.deb` and `.jar` are never concerned, even if `--rpm-dir` is specified.

* *Single format* (`-f cyclonedx`): `--output` is used as is (backward compatibility)
* *Multiple formats* (`-f cyclonedx,spdx,markdown`): `--output` is treated as
  a *base path*; the appropriate extension is added automatically by
  `_formatExtension()` / `_basePath()`

[cols="1,1", options="header"]
|===
|Format |Extension added

|`cyclonedx`
|`.cdx.json`

|`spdx`
|`.spdx.json`

|`spdx3`
|`.spdx3.jsonld`

|`json`
|`.custom.json`

|`markdown`
|`.md`

|`asciidoc`
|`.adoc`

|`html`
|`.html`

|`csv`

[source,dart]

a report is written (whatever the number of CVEs), `1` only if
`--output` is missing or if no scanner produced any result — so that
a caller like `build-dist.sh` under `set -e` does not break the build at the
slightest CVE.

Internal architecture:

[cols="1,3", options="header"]
|===
|Function |Role

|`_runScan()`
|Parses the arguments via `ArgParser`, orchestrates the requested scanners

|`_runScanner()`
|Dispatch to `_runGrype()`, `_runOsv()`, `_runTrivy()`

|`_runGrype()` / `_runOsv()` / `_runTrivy()`
|Launches the scanner via `Process.run()` (catches `ProcessException` if the
binary is not found → explicit message on stderr, no crash),
parses each tool's own JSON, returns a normalised list
`{id, severity, package, published, modified}`. The `── Name ──` banner
is only printed if `--format text` (silent in `sarif` so as not to
pollute the JSON output)

|`_filterByDate()`
|Applies `after` / `before` / `includeUndated` on the chosen date field

|`_enrichFindings()`
|After all scanners, before the filters: gathers the identifiers
(normalised via `_normalizeCveId`) + one `CveSeed` per CVE (CVSS vector,
and for Grype native KEV/EPSS), calls `VulnEnricher.enrich()`
(`lib/vuln_enrichment.dart`), then injects the obtained `ExploitInfo` into
each finding (`v['exploit']`). Best-effort: any exception leaves
`ExploitInfo.empty`. Returns the id → `ExploitInfo` map for the report

|`_filterByExploit()`
|Applies `--only-kev` / `--epss-min` on already enriched findings

|`_cvssFromGrype/Osv/Trivy()`
|Extract `(CVSS vector, base score)` from each scanner's own JSON
(`vulnerability.cvss[]`, `severity[].score`, `CVSS.<src>.V3Vector`)

|`_printScanResults()`
|Sorts by decreasing severity (`Critical` → `Unknown`), or by risk if
`--sort risk`, and displays a text table per scanner — extra
`KEV` / `EPSS` / `PoC` columns (`--format text`)

|`_buildSarifReport()`
|Builds a SARIF 2.1.0 report (one `run` per scanner queried, one
`rule` deduced per vulnerability identifier, `level` via `_sarifLevel()`,
`security-severity` via `_sarifSecurityScore()` — raised to `9.5` if KEV).
Each `result` and `rule` carries the `kev` / `epss` /
`epssPercentile` / `poc` / `cvssExploitability` properties — `--format sarif`

|`_writeScanReport()`
|`--format markdown` / `asciidoc` / `pdf`: receives the `ScanReportGenerator`
(`lib/scan_report_generator.dart`) and writes the file. For `pdf`, first writes
an `.adoc` alongside then calls `renderAsciiDocToPdf()` (shell-out
`asciidoctor-pdf` with `_kPdfThemeYaml`, `extends: default-sans` — cover
page, numbered executive summary + verdict, paginated footer, severity
badges in the report language; synchronised copy of the theme of
`gui/lib/widgets/pdf_report.dart`); `ProcessException` or code ≠ 0 →
keeps the `.adoc`, warns, but does not make the command fail

|`_printSeverityAlerts()`
|Before writing the file (report formats only): lists on stdout
`ScanReportGenerator.alerts()` — one line per unique Critical (red

the `[KEV]` / `EPSS <score>` / `[PoC]` markers, then a count (including the
number of KEV CVEs). `--color auto` (default) = `stdout.hasTerminal && !NO_COLOR`;
`always` / `never` force it. Best-effort, no effect on the exit code

|`_scannerVersion()`
|Short `x.y.z` version of a scanner (best-effort, for the "Tools" header
of the report)

|`_printScanUsage()`
|Displays the subcommand help with examples

`ScanReportGenerator` (`lib/scan_report_generator.dart`) is pure (no I/O
apart from `renderAsciiDocToPdf`): `toMarkdown()` / `toAsciiDoc()` take the
`Map<String, List<…>?>` per scanner (`null` = not run, `[]` = run
with no result) and produce global summary + breakdown by severity +
CVE × scanner matrix. `alerts({keep})` returns the `ScanAlert`s (unique CVE,
worst severity, package, scanners) above a threshold — consumed by
`_printSeverityAlerts` on the CLI side. OSV-Scanner's distro-prefixed
identifiers (`DEBIAN-CVE-…`) are normalised (`_distroPrefixedCveRe`) before
any counting/comparison, as in the GUI dashboard.

`cveNotes()` returns a `Map<String,String>` id → note, rendered as a
"Notes per CVE" section under the matrix: one entry per CVE that Grype reports
without a usable fix (`fixState` ≠ `fixed` and `fixedVersions` empty)
while OSV-Scanner or Trivy carry a fixed version. The runners
(`_runGrype` / `_runOsv` / `_runTrivy`) feed this by adding to each
finding `fixState` + `fixedVersions` (Grype `vulnerability.fix`), the `fixed`
events of the `affected[].ranges[]` ranges (OSV), and `FixedVersion`
split (Trivy). Goal: make explicit that the fixed version of a distribution
advisory is generally that of `unstable`/`testing`, not an update
available for the installed stable release — cf. `usage.en.adoc`, section
"Why the scanners do not find the same CVEs".

==== Exploitability enrichment (`lib/vuln_enrichment.dart`)

`VulnEnricher.enrich(ids, {seed})` returns a `Map<String, ExploitInfo>`

[source,dart]
----
Future<List<Map<String, dynamic>>?> _runGrype(String sbomFile, {bool quiet = false}) async {
  final ProcessResult result;
  try {
    result = await Process.run('grype', [
      sbomFile, '--output', 'json',
      '--platform', 'linux', '--add-cpes-if-none', '--by-cve',
    ]);
  } on ProcessException catch (e) {
    stderr.writeln('grype: not found (${e.message}). ...');
    return null;
  }

----

The Grype options are aligned with the GUI's launcher
(`gui/lib/services/grype_runner.dart`): without `--add-cpes-if-none`, Grype only
matches by PURL and misses CVEs indexed by CPE (e.g. the `flutter` pseudo-package
of a `pubspec.lock`, which has no usable PURL) — this is the
cause of a gap observed between `scan` and the Grype tab on a given SBOM.
`--by-cve` makes it report the CVE ID rather than GHSA, a necessary condition to
align identifiers with OSV-Scanner/Trivy in the cross-scanner
matrix. `--platform linux` has no effect on an SBOM input (kept
for parity). OSV-Scanner (`--format json --sbom`) and Trivy
(`sbom --format json --quiet`) are already invoked like the GUI.

Each scanner has its own JSON format (`matches[]` for grype,
`results[].packages[].vulnerabilities[]` for osv-scanner,
`Results[].Vulnerabilities[]` for trivy); `_runGrype`/`_runOsv`/`_runTrivy`
absorb this heterogeneity and return the same normalised structure.

The failure of a scanner (missing binary, unreadable JSON) does not prevent the
other requested scanners (`--scanner all`) from running.

Exit codes: `0` if no vulnerability in the requested range (all
scanners combined), `1` if at least one found or in case of scanner error.

See `doc/usage.en.adoc` for complete usage examples.


[[sec-scan-per-layer-dev]]
==== Vulnerabilities per layer (`--image`, `--per-layer`) — `lib/layer_scan.dart`

Options: `--image <image>` (mutually exclusive with `--sbom`, which is no longer
mandatory), `--oci-tool` (default `syft`), `--per-layer`,
`--layer-scan <attribute|each>` (default `attribute`), `--layer-mode
<metadata|rootfs>` (only with `--image --per-layer`).

- *`--image`*: `_runSelf()` relaunches this same program (`dart` script —
  `Platform.script` in `.dart`/`.snapshot`/`.dill` passed to
  `Platform.resolvedExecutable` — or compiled executable) with
  `--image … -f cyclonedx -o <tmp>/image.cdx.json [--per-layer
  --layer-mode …]`, output sent back on stderr (stdout may carry
  SARIF). Guarantees an SBOM set identical to that of the normal generation
  without duplicating the pipeline of `main()`. The temporary directory
  is deleted by the local function `quit(code)`, which replaces the
  `exit()`s of `_runScan` after its creation.
- *`LayeredSbomSet.load(globalPath)`* re-reads the set: components of the global one
  (`sbom_generator:layer:index` — CycloneDX properties, SPDX 2.3 / 3.0
  annotations) → `layerByPackage` (`name@version` → layer), summaries
  `sbom_generator:layers:NNN` (digest, instruction), layer SBOMs
  found by their name (`layerFilesOf`: same base, same extension;
  extension-less global → `.cdx.json` layers). `null` without layer
  information → `scan` stops.
- *`attribute`*: usual scan of the global one, then `attributeLayers()` sets
  the `layer` key (index) on each finding (`package` = `name@version`,
  falling back to the name alone if unambiguous — scanners sometimes normalise
  the version).
- *`each`*: `_runScanner()` on each layer SBOM (`quiet: true`,
  a single header per scanner), `layer` set on each finding, lists
  concatenated. The same CVE can therefore appear in several layers.
- *Rendering*: `_printScanResults` adds the `LAYER` column as soon as a
  finding carries `layer`; `_printLayerSummary` (text) and
  `ScanReportGenerator(layers:, layerScanMode:)` rely on
  `summarizeByLayer()` (unique CVEs per layer, normalised id, worst severity
  across scanners); SARIF: `layer` property + mention in the message.

=== `cra` subcommand — Cyber Resilience Act compliance report _(new)_

`_runCra(args)` (dispatched on `arguments.first == 'cra'`) produces a compliance
report with *Regulation (EU) 2024/2847* restricted to the **subset of
requirements that can be automatically verified** from an SBOM. The report
explicitly delimits its scope and **is not a declaration of
conformity** — non-verifiable requirements are only listed as
"manufacturer's responsibility".

All the logic is in `lib/cra_report.dart` (pure, no I/O except the PDF).
`_runCra` is limited to orchestration:

. parses the arguments, validates `--sbom`, `SbomReader.loadJson` (rejects an
  unknown format);
. metadata: `CraMetadata` of the CLI flags `.merge(` `cra.yaml` config `)`,
  the config being `--config` or `./cra.yaml` if it exists; remaining gaps
  are filled from the SBOM's `metadata.component` / `metadata.supplier`;
. if `--scan`: `_runScanner` loop over `--scanner` (default `grype`) then
  `_enrichFindings(... poc: false, quiet: true)`;
. `Process.run('sbomqs', ['score', '--basic', sbom])` best-effort;
. builds `CraReportGenerator` and serialises: `json` → stdout or `-o`
  (exit 2 if verdict `fail`); `asciidoc` / `pdf` → writes the `.adoc` then
  `renderAsciiDocToPdf`;
. `stdout`: `Verdict (verified scope): …` + `exit(verdict == fail ? 2 : 0)`.

Checklist cross-referencing four frameworks: **BSI TR-03183-2** (data
fields per component: name, version, supplier, unique identifier
PURL/CPE, hash, license, dependency relationships), **CRA Annex I §2**
(inventory of known vulnerabilities, availability of fixes),
**NTIA 2021** (seven minimum elements), **CRA art. 14** (any CVE in the
CISA KEV catalog → ENISA notification within 24 h).

|===
|Member of `cra_report.dart` |Role

[[sec-option-per-layer]]
=== `--per-layer` / `--layer-mode` options

Validation (after that of `--oci-tool`):

- `--layer-mode` without `--per-layer` → error;
- `--per-layer` with `--binary` or a `--image` of type `OciRefType.binary`
  → error ("a standalone binary has no layers");
- `--layer-mode metadata` with a backend outside `metadataLayerTools`
  (`syft`, `trivy`) → error; without `--layer-mode`, the mode is `metadata`
  for syft/trivy and `rootfs` otherwise (console message);
- `rootfs` mode on a registry reference with a backend other than
  skopeo: `skopeo` must be available (local copy of the layers).

Flow: the per-layer analysis follows the usual OCI analysis (the global
SBOM remains that of a run without `--per-layer`, annotated). The
`--license-map` / `--supplier` overrides are applied to the layer
components via `LayerAnalysis.map`. The generation loop is factored into
a local function `writeAll(pkgs, deps, pathFor, layers:, label:)`,
called for the global one then for each layer. The document UUIDs are
drawn *before* any write (global ↔ layers cross-links), which
makes it possible to write the *global first*: it is the first
`SBOM written → …` of the output, the one the GUI tabs open by
default. Layer files: `layerFileBase(_basePath(outputPath), layer,
total)` + `_formatExtension(fmt)`, i.e. `<base>.layer-NN-<digest12><ext>`.
A layer's dependencies are resolved on its own components only. `--sign`
also signs the first format of each layer; `--min-quality-score` only
concerns the global one.

=== `--concurrency` / `-c` option _(new)_

Controls the number of tasks processed simultaneously (default: `4`, `0` = unlimited).
Implemented via the `_Semaphore` class:

[source,dart]
----
class _Semaphore {
  _Semaphore(int count) : _count = count;
  int _count;
  final _waiters = <Completer<void>>[];
  Future<void> acquire() async {
    if (_count > 0) { _count--; return; }
    final waiter = Completer<void>();
    _waiters.add(waiter);
    await waiter.future;
  }
  void release() {
    if (_waiters.isNotEmpty) _waiters.removeAt(0).complete();
    else _count++;
  }
}
----

The main loop is replaced by:

[source,dart]
----
final sem = _Semaphore(concurrencyN == 0 ? mainRefs.length : concurrencyN);
final rawResults = await Future.wait(
  List<Future<Package?>>.generate(mainRefs.length, (i) async {
    await sem.acquire();
    try {
      return await _processRef(mainRefs[i], …);
    } finally { sem.release(); }
  }),
);
----

[NOTE]
====
`Future.wait(List.generate(...))` preserves order: `rawResults[i]` matches
`mainRefs[i]`.
====

=== CycloneDX 1.7 support

The 1.6 JSON schema has `additionalProperties: false` everywhere: the 1.7-specific fields
(`citations`, `definitions.patents`, `components[].patentAssertions`,
`metadata.distributionConstraints`) are therefore *never* emitted in 1.6, and `generate()`
throws an `ArgumentError` if `tlp`/`citationSource`/`patentsByPackageName` are provided without
`specVersion: '1.7'`. `CycloneDxGenerator.supportedSpecVersions` and
`.validTlpClassifications` expose the valid values for the CLI.

`PatentAssertion` (patentNumber, jurisdiction, legalStatus, assertionType) is validated
before generation (ST.3 regex for `jurisdiction`, CycloneDX enums for the rest). Each
referenced patent is deduplicated in `definitions.patents[]` by `bom-ref`
(`patent-<normalised number>`); the corresponding component receives a
`patentAssertions[]` entry pointing to that `bom-ref`. Notable point: the `asserter` field must
be disambiguated with an empty `url: []`, otherwise the schema validates it simultaneously as
`organizationalEntity` *and* `organizationalContact` and the strict `oneOf` fails.

The citation (`--image` + `--cyclonedx-version 1.7`) attributes `/components` to the `bom-ref`
of the OCI tool used (`--oci-tool`), added as a second `tools.components[]` in the
metadata.

=== `group` field (Maven components)

`WheelPackage(packageType: 'maven')` stores the Maven coordinates in the form
`"groupId:artifactId"` in `Package.name` (internal convention shared by
`maven_parser.dart`, `jar_parser.dart`, `oci_parser.dart`). `_packageToComponent` splits this
`name` into two dedicated CycloneDX fields — `group: groupId` and `name: artifactId` — instead
of leaving the groupId concatenated in `name`, to follow the standard CycloneDX convention
(`group` field meant exactly for this) and get closer to what syft/trivy emit.
`Package.name` itself is not modified: the other generators (SPDX, Markdown, CSV…)
keep displaying `"groupId:artifactId"` as is.

Corollary on the reading side: `sbom_reader.dart` (`_cdxComponent`) recombines `group` + `name`
into `"groupId:artifactId"` as soon as a component has `packageType == 'maven'` and a non-empty
`group` field — otherwise the groupId would be silently lost when re-reading a CycloneDX
document generated this way (`convert`, `merge`, GUI…).

[[sec-spdx-generator]]
== `lib/spdx_generator.dart` — SPDX 2.3 generator

Signature: `List<Package>`, plus `osInfo` (`OsInfo?`, optional — see
<<sec-osinfo-oci-parser>>). Normalisation via `LicenseNormalizer.toSpdxExpression()`.
Type-aware annotation:

[source,dart]
----
String _annotationComment(Package pkg) {
  if (pkg is RpmPackage)
    return 'arch=${pkg.arch}; epoch=${pkg.epoch}; release=${pkg.release}…';
  if (pkg is WheelPackage)
    return '${pkg.packageType == "pypi" ? "pypi" : "source"}:platform=${pkg.arch}';
  if (pkg is DebPackage)
    return 'deb:arch=${pkg.arch}';
}
----

When `osInfo` is provided, `_osToSpdx()` adds a package
`primaryPackagePurpose: "OPERATING-SYSTEM"` with a `DESCRIBES` relationship
from `SPDXRef-DOCUMENT`. This package's `SPDXID` is prefixed
`SPDXRef-OperatingSystem-` (and not `SPDXRef-Package-` like the others) —
this is the precise prefix that Trivy recognises for the "os-pkgs" class in
`trivy sbom` mode; `primaryPackagePurpose` alone is not enough (empirically
checked, see <<sec-osinfo-oci-parser>>).

`package.supplier` is **always emitted**: `Organization: <vendor>` if known,
otherwise `NOASSERTION` — the SPDX 2.3 spec asks for the explicit value when the
supplier is unknown (rather than omitting the field), and this is what
the NTIA minimum elements and `sbomqs` expect. Same for the OS package.
`checksums` is emitted from `pkg.hashes` (`spdx2Alg`: `SHA-256` → `SHA256`).

== `lib/spdx3_generator.dart` — SPDX 3.0 JSON-LD generator

Signature: `List<Package>`, plus `osInfo` (`OsInfo?`, optional). Normalisation via `LicenseNormalizer.toSpdxExpression()`.
Same annotation logic as SPDX 2.3 (`DebPackage` branch included).
`_buildVendorElements` creates one `Organization` node per unique `pkg.vendor` value
(works for all types).

When `osInfo` is provided, `_osToElement()` adds a
`software:Package` element with `software:primaryPurpose: "operatingSystem"`,
included in the `SpdxDocument`'s `rootElement` and in the `describes` relationship.
Correct representation according to the SPDX 3.0 spec, but *Trivy cannot read
SPDX 3.0 JSON-LD SBOMs at all* (`trivy sbom` fails with `SBOM decode
error: unknown scanning is not yet supported`, independently of this
component) — a Trivy limitation, unrelated to `sbom_generator`.

== `lib/simple_json_generator.dart` — Custom JSON generator

Signature: `List<Package>`. The `packageType` field is included in each entry.
The RPM-specific fields (`release`, `epoch`, `buildTime`) are added
conditionally:

== Data flows — concrete examples

=== RPM: `bash` from a .rpm file

....
1. Detection: .rpm → RpmParser.parsePackage()
2. rpm -qp --queryformat '…' → "bash|5.1.8|6.el9|x86_64|(none)|GPL-3.0-or-later|…"
3. RpmPackage: bomRef="pkg-bash-5.1.8-6.el9-x86_64", purl="pkg:rpm/bash@5.1.8-6.el9?arch=x86_64"
4. LicenseNormalizer.toCycloneDxLicenses("GPL-3.0-or-later")
   → normalised = "GPL-3.0-or-later" (no boolean operator)
   → mapped = "GPL-3.0-or-later" (in kSpdxLicenseIds → id)
   → {"license": {"id": "GPL-3.0-or-later"}}
....

=== Python wheel: `requests-2.28.2-py3-none-any.whl`

....
1. Detection: .whl → WheelParser.parseWheelFile()
2. python3 zipfile → requests-2.28.2.dist-info/METADATA
3. _parseRfc822() → {name: "requests", version: "2.28.2", license: "Apache-2.0", …}
4. _platformFromFilename() → "any" (last segment before .whl)
5. WheelPackage: packageType='pypi', bomRef="pkg-pypi-requests-2.28.2"
                  purl="pkg:pypi/requests@2.28.2"
....

=== Generic archive: `mariadb-11.4.8-linux-systemd-x86_64.tar.gz`

....
1. Detection: .tar.gz → TarParser.parseTarFile()
2. python3 tarfile: no PKG-INFO → type='generic'
   COPYING file found → 2 KB extracted
3. _parseFilename():
   segments=[mariadb, 11.4.8, linux, systemd, x86_64]
   versionIdx=1 ("11.4.8" ≅ ^\d+\.\d+)
   platform filtering: linux, systemd, x86_64 removed
   → name="mariadb", version="11.4.8", arch="x86_64"
4. _identifyLicense(COPYING):
   title[:300] contains "GNU GENERAL PUBLIC LICENSE" + "Version 2"
   → "GPL-2.0-only"
5. WheelPackage: packageType='source', purl="pkg:generic/mariadb@11.4.8"
....

=== Python sdist: `Django-4.2.1.tar.gz`

....
1. Detection: .tar.gz → TarParser.parseTarFile()
2. python3 tarfile: PKG-INFO found → type='python', RFC 822 content
3. Delegation to WheelParser.parseMetadataText(path, content)
4. WheelPackage: packageType='pypi', purl="pkg:pypi/django@4.2.1"
....

=== Debian package: `libssl3_3.0.1-1_amd64.deb`

....
1. Detection: .deb → DebParser.parseDebFile()
2. dpkg-deb -f → RFC 822 control: "Package: libssl3\nVersion: 3.0.1-1\n..."
3. _parseControl() → {Package: libssl3, Version: 3.0.1-1, Architecture: amd64, …}
4. _parseDependsList("libc6 (>= 2.17), libgcc-s1") → ["libc6", "libgcc-s1"]
5. DebPackage: bomRef="pkg-deb-libssl3-3.0.1-1-amd64",
               purl="pkg:deb/libssl3@3.0.1-1?arch=amd64"
....

=== Requirements.txt: `/opt/reqs/requirements.txt`

....
1. Detection: .txt → RequirementsParser pre-expansion (before the concurrent loop)
2. Line-by-line reading: "requests==2.28.0\nnumpy>=1.24\nflask\n"
3. _parseLine("requests==2.28.0") → WheelPackage(name="requests", version="2.28.0",
                                                  packageType="pypi")
4. _parseLine("flask") → WheelPackage(name="flask", version="", packageType="pypi")
5. Results added to preloadedPackages (then packages after the main loop)
....

=== OCI image: `nginx:latest` via syft

....
1. OCI detection: --image nginx:latest (OciRefType.registry)
2. Process.run('syft', ['nginx:latest', '--output', 'json'])
3. _parseSyft() traverses artifacts[]:
   e.g. {name: "bash", version: "5.1.8", type: "rpm", purl: "pkg:rpm/rhel/bash@5.1.8",
        licenses: [{spdxExpression: "GPL-3.0-or-later"}], metadata: {Arch: "x86_64"}}
4. OciPackage(name="bash", version="5.1.8", packageType="rpm",
              purlOverride="pkg:rpm/rhel/bash@5.1.8",
              bomRef="pkg-oci-rpm-bash-5.1.8")
5. Results added to ociPackages → merged into packages before deduplication
....

== Pitfalls and design decisions

=== 1. `|` separator in SUMMARY (RPM)

`SUMMARY` may contain `|`. It is placed last in `_queryFormat`
and the fragments ≥ index 12 are rejoined.

=== 2. Duplicate bomRefs (RPM)

Same NEVRA in several repositories → same `bomRef` → forbidden by CycloneDX.
The deduplication in `main()` removes the second copy.

=== 3. `LicenseRef-*` in CycloneDX

`license.id` is validated against the official SPDX list. `LicenseRef-*` is not
part of it (in the schema embedded in sbomqs v2.0.6). Use
`{"license": {"name": "…"}}` instead.

=== 4. `acknowledgement` field (CycloneDX 1.6.1)

Added after the version of the schema embedded in sbomqs. Using it causes
a validation error. Do not use it.

=== 5. `_capabilityName` and Python RPM modules

`split(RegExp(r'[\s(]'))` would truncate `python3dist(lxml)` to `python3dist`,
creating false positives. The split on `\s+[<>=!]` preserves the parentheses.

=== 6. GPL → LGPL false positive in license detection

The GPL-2.0 text mentions "GNU Library General Public License" in its
"How to Apply" section. LGPL detection only looks at the first 300
characters (document title), not the complete body.

=== 7. Intra-list Python dependencies

Resolution works if names are normalised consistently
(PEP 503). `WheelPackage.provides` contains the normalised name; `Requires-Dist`
is also normalised at parsing. `buildDependencies` additionally adds the raw
`pkg.name` to `providesMap`, covering both forms.

=== 8. Requirements.txt: 1:N cardinality

A single `.txt` file may produce N packages. The concurrent loop models
`Future<Package?>` (1 ref → 0 or 1 result), incompatible with 1:N
cardinality. Solution: pre-expansion of the `.txt` files before the loop into `preloadedPackages`.

=== 9. `License` field absent in many `.deb`

The Debian standard does not make the `License` field mandatory in
`DEBIAN/control`. `DebPackage.license` will often be empty, which gives
`NOASSERTION` in SPDX and an empty `licenses` list in CycloneDX —
compliant behaviour, not an error.

=== 10. Order preserved by `Future.wait(List.generate(...))`

`Future.wait` guarantees that the result at index `i` matches input `i`.
The order of appearance in the final SBOM is therefore identical to the order of the
input file, despite concurrent processing.

=== 11. Translating messages: what must stay untouched

Since the project is bilingual (see <<sec-i18n>>), any message passes through `tr()`.
But some texts are *contracts* with other programs and must not
be translated: the `SBOM written → <path>  (<size> KB)` line and the
`] n/m  p%  label` progress bar (parsed by the GUI), the layer descriptions
and the `couche` labels written in SBOMs (parsed by `gui/lib/models/layer_nav.dart`),
the property names, the JSON keys and the SARIF identifiers. When a
text becomes translatable, check the GUI regexes
(`grep -rn "RegExp" gui/lib/services`) before wrapping it in `tr()`.

The OCI analysis runs *outside* the concurrent `_Semaphore` loop:

the former sequential loop. With `--concurrency 0` (unlimited), all
inputs are launched simultaneously.

=== Known limits

* *No transitive resolution*: only dependencies between packages present
  in the list are included.
* *Approximate CPEs*: syntactically valid, may differ from the official NVD
  entries.
* *Heuristic archive licenses*: detection from LICENSE/COPYING files
  is based on text patterns, not on an exhaustive analysis.
* *`License` field absent in `.deb`*: most Debian packages do not include
  a `License` field in their `control` — `DebPackage.license` will be empty, which
  produces `NOASSERTION` in SPDX.
* *No file existence check*: if a `.whl`, `.tar.gz`,
  `.zip` or `.deb` path does not exist, the subprocess fails and the package is counted as a
  failure.
* *Absent licenses in OCI images (skopeo)*: `_parseDpkgStatus` does not read
  the `copyright` files; `_parseRpmRoot` only has the `%{LICENSE}` fields
  of the RPM registry — same gap as with `DebPackage`.
* *OCI analysis not parallelised*: the `OciParser.parseImage()` call is sequential
  and blocking; `--concurrency` only applies to `--input` entries.

== Checklist before making a change

* [ ] `dart analyze lib/ bin/ test/` passes without error or warning (`No issues found!`)
* [ ] `dart format --output=none lib/ bin/` passes without differences
* [ ] `dart test` — all green (some integration tests skip cleanly
  depending on the environment)
* [ ] Any new user-visible text has its two versions `tr('fr', 'en')` — and has not
  broken a contract (`SBOM written → …` line, progress bar, layer
  texts, JSON keys): see pitfall 11
* [ ] Documentation updated in both languages (`*.adoc` and `*.en.adoc`, `README*.md`,
  `CHANGELOG*.md`)
* [ ] Test on the 5 3PP archives (name, version, arch, license correct)
* [ ] Test with a mixed list RPM + .whl + .tar.gz + .zip + .deb + .jar + requirements.txt + `--image`
* [ ] Test with Go (`go.sum`, `go.mod`), npm (`package-lock.json`), yarn (`yarn.lock`), Maven (`pom.xml`), Dart/Flutter (`pubspec.lock`, `pubspec.yaml`) manifests
* [ ] Test of the `convert` subcommand: CycloneDX → SPDX, SPDX → CycloneDX, all → CSV
* [ ] Test of the `licenses` subcommand: grouping, copyleft warning, packages without license
* [ ] Test of the `validate` subcommand: valid file, invalid, strict mode
* [ ] Test of the `scan` subcommand: each scanner (`grype`, `osv`, `trivy`, `all`),
  date filters, `--include-undated`
* [ ] If `--rpm-dir` is modified: check exact resolution (NEVRA), resolution
  by name, multi-match warning, `rpm -q` fallback if absent
* [ ] The CycloneDX SBOM passes `sbom_schema_valid: 10.0` in sbomqs
* [ ] No duplicate `bom-ref` in the CycloneDX output
* [ ] If `LicenseNormalizer` is modified: re-run `test/unit/license_normalizer_test.dart`
  (23 cases)
* [ ] If `identifyArchiveLicense` is modified: check that GPL-2.0 (MariaDB COPYING)
  is not detected as LGPL
* [ ] If `parseArchiveFilename` is modified: check the 5 3PP cases of the table
  in `archive_helpers_test.dart`
* [ ] If `_capabilityName` is modified: check `python3dist(lxml) >= 3.0` →
  `python3dist(lxml)`
* [ ] If a package type is added: update `models.dart`, all the generators
  (`if (pkg is …)`), `bin/sbom_generator.dart` (dispatch + tool check) and this document
* [ ] If `OciParser` or `--image`/`--oci-tool` is modified: test the four backends
  (syft, trivy, skopeo, cdxgen) with registry, tar and OCI layout; if the OS detection
  (`OsInfo`) is touched, re-check with `trivy sbom` on the produced SBOM that
  the "os-pkgs" class is indeed detected (not only that the OS component is
  present in the JSON — see <<sec-osinfo-oci-parser>>)
* [ ] If a manifest parser (1:N) is added: add it to the pre-expansion block in
  `main()` with its `_isXxx()` helper — do not go through the concurrent loop

== Build and deployment

[source,bash]
----
# Development (JIT, compiles on the fly)
dart run bin/sbom_generator.dart -i packages.txt

# Standalone native binary (AOT, ~30 s compilation)
dart compile exe bin/sbom_generator.dart -o sbom_generator

# Tests
dart test                            # all the tests
dart test test/unit/                 # unit only
dart test test/integration/          # integration only

# Static analysis
dart analyze

# Formatting
dart format lib/ bin/ test/
dart format --output=none lib/ bin/ test/   # CI mode (no modification)
----
